# Candid Agent 计划多专家审核

2026-10-14：字幕修复与连续语音扩展已另行完成新的三专家审核，见 [最新审核记录](VOICE_CONVERSATION_REVIEW.md)。本文件下文为原计划历史记录，不代表新语音功能的实现或验收。

日期：2026 年 10 月 13 日。审核对象：[Agent 完成计划](AGENT_COMPLETION_PLAN.md)。

三个独立审核代理分别从 Agent 架构、移动端运行和交付顺序检查计划，并结合现有源码核对基础能力。总体方向保留，修订后均通过各自范围的复核。本次完成的是计划和依赖审核；功能开发、模型接口可用性及真机验证仍按计划交付。

用户随后要求模型、供应商与关键需求先汇报确认。计划已增加开发前确认节点：ASR/TTS 模型、渠道、时间戳、说话人和实时性等仍待用户决定；此前按参考适配器提出的片段回放或轮次式语音只是候选。三位专家的架构复核不等于这些需求和选型已获用户确认。

后续用户确认了只考虑安克 SOP 当前已列模型、实时仅显示文字、最终必须分人以及保留粤语原话。当前唯一 ASR 型号缺少真正实时输入和自动分人能力，原两模型方案未能在这一范围内成立；相关缺口已列入计划与选型说明。这些新增需求尚未得到可实现方案，不能沿用先前架构复核结论宣称完整 ASR 已可交付。

用户进一步解除仅限安克已列模型的条件，允许比较额外接入 OpenRouter 的价值。计划与选型说明已转为比较原生实时服务及 OpenRouter 文件转写；这只授权选型调研，具体组合和新增接入仍待确认。分人、粤语原话、时间戳和长录音要求继续保留。

## 审核范围与结果

| 专家视角 | 初审意见 | 复核结果 |
|---|---|---|
| Agent 架构 | 2 项 P1、3 项 P2，涉及指令边界、任务串行、摘要失效、版本快照和引用 | 原 5 项已解决，未发现新增明确矛盾 |
| 移动端运行 | 2 项 P1、3 项 P2，涉及说话人归属、长音频、手机录音、上传恢复与真机连接 | 原 5 项已解决；设备回执依赖经再次修订后通过 |

P1 表示开始对应阶段前需要澄清，否则可能阻塞流程或造成明显错误；P2 表示会增加返工或使交付承诺不准确的缺口。初审共 14 条，复核新增的设备回执问题由两位专家同时指出，合并为 1 条。下表记录 15 条意见在计划中的处理，均未标记为代码功能已完成。

## 意见处理记录

| 级别 | 原计划缺口 | 采用的修订 |
|---|---|---|
| P1 | 可信 Skill 与外部资料的指令边界未写明 | 阶段二把基础规则与人格分开；受控 Skill 是流程指令，网页、PDF、转写与记忆作为数据；搜索参数不默认附带无关个人记忆 |
| P1 | 同一对话多个任务可能互相覆盖 | 阶段四限定一个活动任务；补充、取消后新建、排队有明确含义；事件和结果绑定任务与轮次 |
| P1 | 未知说话人无法进入现有只读取本人片段的复盘 | 七 A 区分会话总结与本人记忆；个人草稿只引用已确认本人片段，不以设备通道推断归属 |
| P1 | 长录音与实际 ASR 输入格式、时间精度不匹配 | 七 A 增加解码、重采样、分片、原音频偏移与重叠去重；先交付真实片段边界回放，句级对齐待能力确认 |
| P1 | Monid 不可用会阻塞文本流程及后续语音 | 五 A 独立接收用户资料，阶段六先用本人文字复述完成准备、复盘、确认和再次引用；自动调研随后增强 |
| P1 | 记忆交接遗漏场次与转写的写入、修订责任 | 阶段一新增数据所有权表、统一读写适配器、场次创建、证据写入和版本修订及失效约定 |
| P2 | 修订或删除后的旧记忆仍可能留在摘要与检查点 | 阶段三记录资料版本，恢复和新回答前校验引用状态，失效时移除内容或重建摘要 |
| P2 | 只记录 Skill 版本号不能恢复旧正文 | 阶段二保存正文快照或可读取旧版本，并记录人格、模型配置与工具端点定义版本 |
| P2 | 报告来源要求缺少可实现的引用校验 | 阶段五校验资料和片段 ID 的存在性、可访问性及实际获取状态，区分摘要、正文与数据库结果 |
| P2 | 把手机麦克风录音描述为已有功能 | 当前基础改为设备同步、上传和本人文字复述已有代码；七 A 明确开发手机录音与权限、音频打断处理 |
| P2 | 上传中断与后端任务恢复混在一起 | 七 A 在上传确认入库后启动任务，未完成上传保留本机文件，并核对服务端状态再续传或安全重传 |
| P2 | 本机真机连接条件未明确 | 阶段一补充模拟器 localhost、真机使用 Mac 局域网地址、LAN 监听与 Debug 安装说明 |
| P2 | Skill 与摘要早于任务模型，容易重复实现状态 | 阶段一先建立最小持久化任务记录，阶段四再补事件通道与完整恢复 |
| P2 | TTS 硬依赖安克设备接入 | 阶段七拆成七 A 文件/手机输入与七 B 设备输入；阶段八只依赖七 A |
| P2 | 拆分设备后，动作回执仍列为 TTS 必达条件 | 动作请求与回执移入七 B；阶段八只交付手机轮次式语音，消除残留依赖 |

## 源码核对依据

- [当前 Agent 的基础规则](../backend/agent.py)：已将工具资料中的指令视为数据，重构需保留；当前同一对话采用执行锁，持久化任务需延续该约束。
- [转写写入与分析入口](../backend/app.py)：现有转写写入直接使用本机存储，更新资料会使推断产物失效；分析入口要求本人片段。
- [记忆与分析处理](../backend/memory.py)：当前分析及证据处理读取 `speaker=self`，不能把未知说话人的 ASR 结果直接当作本人记忆。
- [ASR 参考适配器](../backend/asr.py)：当前要求 16 kHz 单声道 PCM16 WAV、时长不超过 5 分钟，返回整段文字、未知说话人及片段边界；不证明安克网关具备相同限制或句级时间戳。
- [设备音频转换](../ios/CanDid/SoundcoreAudio.swift)、[当前录音页面](../ios/CanDid/SoundcoreViews.swift)：现有路径是设备文件转换及同步，文字复述入口可复用；未发现手机麦克风录制实现。
- [App 上传](../ios/CanDid/API.swift)、[本机后端启动](../backend/run.py)：现有 App 以普通上传发送文件，后端已提供 LAN 启动选项；恢复上传和真机连接仍需按计划落实。

## 审核后的开发顺序

Agent 结构与最小任务记录 → SOUL 与 Skill → 记忆适配与上下文 → 完整任务恢复 → 用户资料输入 → 文本准备、复盘与记忆确认 → Monid 公司调研及准备增强 → 平台动态与产品反馈 → 文件和手机录音、ASR → TTS 与手机轮次式语音 → 安克设备输入 → 完整交付。

Monid 账号或设备暂不可用时，继续开发已有资料和手机输入流程；自动公司调研、设备接入仍保留在完整交付范围。第一项继续是阶段一，未要求提前建设生产队列、技能市场、实时语音或正式多用户登录。

尚待对应阶段确认的外部条件包括 Monid 账号下的端点和计价、安克 ASR/TTS 的实际协议与能力、SDK 授权及真机设备。三位专家和主审均只阅读计划及源码，未运行软件测试或调用付费接口。
