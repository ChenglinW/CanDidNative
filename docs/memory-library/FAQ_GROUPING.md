# FAQ 相似问题分组文档对齐

2026-10-16。本记录依据当前工作区源码静态核对，扩展现行「我／FAQ／背景资料」记忆库约定；保持 Warm 视觉、原生导航、既有组件与设计 tokens，不恢复早期「素材／跨场发现」顶部分段。当前实现仍在测试，本记录不代表构建、运行、供应商、部署或真机验收通过。

## 条目与分组

- `backend/memory_library.py` 的 `Library.snapshot` 以 `library_items` 提供条目，同时返回 `question_grouping`。旧 `assets` 通过 `migrate_legacy` 迁入或补齐元数据，保留旧 ID、范围、人工说法及历史版本；分组不另建回答副本。
- `backend/question_grouping.py` 从当前用户的 active FAQ 读取原问题（缺少时使用标题），要求有引用且引用均为 current；存在源录音时排除 fixture、practice 和未同意记录。销售与面试分别分组。
- 当前策略为 Qwen3.7 embedding、Top 15 候选边和平均连接阈值 0.6646；源码中 fallback／merge 实验助手不参与当前源码路由。此处只描述配置，不重述实验效果或将其视为本轮验证。
- 分组结果只保存成员 ID，组标题来自成员条目；组不生成统一答案，不改成员的说法、依据、客户范围、版本、练习或实战记录。相似问法可以同组，各客户事实仍由原条目和来源范围约束；分组不授予工作区新的读取权限。
- 输入指纹变化时不展示旧分组，先以单条组返回并提交后台整理。读取路径不调用 embedding 网络；后台工作执行 embedding，按用户、文本哈希和模型缓存，写入前再次核对指纹并清理失效缓存。

## 现行页面衔接

`ios/CanDid/MemoryLibrary.swift` 的 FAQ 页接收分组，未出现在已保存分组中的 FAQ 作为单条组保留，避免分组等待、依据变化或整理失败使原条目消失。待改进区仍按原条目显示，默认两条；整理中与失败有文字反馈，失败／中断／取消任务提供继续整理入口。

按问题浏览进入组；按主题进入包含该主题成员的组，同一组可能出现在多个主题下。主题数字当前为可复用条目数，不是组数；组行的「条问法」是成员条目数，「场沟通」是不同源 session 数，不是客户人数或模型调用数。搜索匹配标题、说法、主题和原问题，当前直接展示匹配的条目，待改进与可复用条目继续分区。组行与组页不替代各条目的独立状态。

组详情说明「相似问法放在一起，每次回答与资料依据分别保留」，逐条显示来源录音标题（不可用时显示「沟通记录」）、条目入口及最多四行说法预览；进入原 FAQ 详情查看完整内容。它没有客户身份识别承诺，也不把组内一条有效说法解释为其他成员已经有效。

## 保留能力与边界

原 FAQ 详情仍按 item ID 编辑与恢复版本、关联背景资料、设置会前提醒、查看实战记录、Mock 练习及回听原文；说法、依据、效果状态继续分别保存。Mock 记录仍明确不计入实战。背景资料仍保留文件文字／Apple Vision 本机 OCR、逐页核对、原文件、上传新版、同步与历史恢复；本轮分组不替代这些流程，也不新增逐组确认步骤。AI 新形成的跨场个人结论仍遵循既有集中确认规则。
