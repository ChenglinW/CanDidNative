# 阶段二：人格与固定沟通流程

日期：2026-10-13。当前代码为 `agent-runtime@2`。

## 本轮用户确认

- 人格沿用现有 Candid：温暖、自然、具体、克制的中文沟通伙伴，先回应当前问题，只追问关键缺口。
- Skill 对用户透明，只保留固定的后台能力，不设置 Skill 名称列表、选择器或技能市场。已有“准备下一场”“复盘上一场”仍是自然语言快捷入口。
- 输出兼顾自然对话和组织结构，需要时使用提纲、依据、建议与不确定项，不机械套完整模板。
- 候选表达只生成回答；用户点击保留才写入 L2 草稿，随后单独确认才成为 L3。

这项确认替代原计划中 App 手动选择 Skill 的要求。

## 代码与行为

| 位置 | 用途 |
|---|---|
| `backend/agent_config/SOUL.md` | 可编辑人格，沿用已确认的身份和语气 |
| `backend/agent_runtime/rules.py` | 独立的基础运行规则与指令/资料边界 |
| `backend/agent_runtime/skills.py` | 固定白名单、简介索引、正文按需读取、输入校验和版本校验 |
| `backend/skills/*/skill.json` | 名称、简介、版本、输入、工具权限、依赖与输出要求 |
| `backend/skills/*/SKILL.md` | 各流程的正文 |
| `backend/tools/skill_tools.py` | 内部 `run_skill` 加载工具 |
| `backend/agent_runtime/runtime.py` | 自动加载、权限限制、快照与重试接续 |
| `scripts/update-skill-manifest.py` | 正文修改后更新版本号及内容指纹 |

固定流程共有四个：

| 后台流程 | 当前状态 | 行为 |
|---|---|---|
| `communication_prep` | 可供 Agent 按需加载 | 用当前资料和相关记忆准备目标、提纲、问题与表达 |
| `communication_review` | 可供 Agent 按需加载 | 按本人原文或复述复盘，区分依据与推断 |
| `memory_draft` | 可供 Agent 按需加载 | 整理有来源的候选表达，保留不确定项，不自动写入 |
| `company_research` | 依赖待接入 | 等待公司搜索、正文读取和公司补全三个业务工具 |

新任务先加载人格与固定流程简介，初始提示不包含四份流程正文。Agent 根据用户问题调用内部 `run_skill`，后端只从固定目录读取校验通过的正文，再以受控流程加入模型上下文。外部网页、Monid 教程、记忆、PDF 和转写均作为资料，不会被当作可安装或可执行的 Candid 流程。

内部加载步骤不会进入 App 的 activity 或回答的 tool_steps；实际记忆查询仍保留原有来源展示。一轮消息只激活一个流程，加载后工具集合被限制为该流程的允许范围；流程本身不能提供额外权限、修改身份或增加写入工具。下一轮消息按新目标重新选择。普通问题可直接自然回答。

后台提供鉴权后的 `GET /v1/agent/skills` 供开发查看元信息与依赖状态。它不是 App 的 Skill 选择界面，也不返回流程正文。现有 App 不需要修改、重新构建或展示技术名词。

## 人格与个人偏好

`SOUL.md` 只描述共享身份、语气和回答习惯，基础运行规则不从该文件读取。修改它无需修改执行代码；新任务读取新内容，已有任务的版本快照保持不变。

称呼、表达偏好和沟通目标单独放在当前用户的 profile.agent_preferences 中，通过已有鉴权的 `PATCH /v1/profile` 保存。允许 display_name、answer_style（natural/concise/detailed）及 communication_goal；它们不会改写共享人格，也不能改变工具权限。默认使用 natural。当前 App 尚未增加专门的偏好编辑界面，接口可供后续设置页接入。

## 版本与重试

任务持久化保存人格原文及指纹、固定索引、基础规则版本、预算、模型配置、工具定义与记忆适配器版本。激活流程时，再保存其完整正文、输入、工具范围和版本到 active_skill_snapshot 与 skill_load_history 中，不保存服务 Key。

同一请求 ID 的手动重试使用原任务的提示、预算及已激活流程正文。模型端点、工具定义或基础运行规则发生变化时明确中断，要求新建消息；不悄悄换成新配置。尚未读取的旧流程若已无法获得匹配版本，也明确报版本不可用。任务重试仍是重新执行，完整检查点恢复与事件通道属于阶段四。

## 修改方法

修改人格：直接编辑 `backend/agent_config/SOUL.md`。新任务自动读取，不需要更改 Python。

修改已批准的流程：编辑该目录的 SKILL.md 和必要的元信息，再更新正文指纹与版本号，例如：

```sh
python3 scripts/update-skill-manifest.py communication_prep --version 1.0.1
```

修改正文时必须使用新版本号，正文与指纹不匹配会被拒绝加载。当前固定白名单仅包含上述四个流程；增加流程或实际业务工具按需求确认后另行修改，不自动从第三方下载、安装或启用。

## Monid 配置与剩余依赖

本轮用户提供的 Monid Key 已保存到 `.env.monid.local`，权限 0600，`.env.*.local` 由 Git 忽略。API 地址与 Bearer 鉴权方式按官方 CLI 0.1.7 源码核对；只读 GET /v1/auth/whoami 返回 HTTP 200，未提交抓取任务。配置与结果见 [Monid 接入准备](MONID_SETUP.md) 和 [鉴权结果](MONID_SETUP_RESULT.json)。

公司调研仍需确定供应商的具体业务端点、资料范围、数量限制及费用预算，并接入对应业务工具、异步状态和来源校验。Key 可用不等于调研闭环已完成。

## 启动与验证边界

继续遵循用户“不要测试软件，能打开就行”的要求：本轮做源文件语法解析、JSON 格式检查、后端启动及健康/能力元信息读取；没有运行 pytest、UI 自动化或真实 Agent 对话，没有调用文本模型或提交 Monid 抓取任务。启动结果单独记录，不将代码落地称作功能验收通过。

后续测试团队需要核对自然请求的流程选择、正文按需读取、内部步骤隐藏、来源显示、权限限制及旧版本重试；这些项目本轮没有执行。

实际启动结果：`/health` 返回 ok、`/docs` 返回 HTTP 200；固定索引返回三个可用流程及一个依赖待接入的公司调研流程，正文指纹与元信息一致。离线 OpenAPI 已刷新，见 [阶段二启动记录](AGENT_STAGE_TWO_STARTUP.json)。
