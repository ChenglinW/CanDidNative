# PDF 上传与解析修复

2026-10-16。用户反馈上传解析异常，但未提供具体失败文件或入口；此次修复覆盖个人资料、项目资料及旧空间资料导入。没有推断用户实际 PDF 的内容或类型。

## 复现与修复

1. 旧 PDF 解析以 `is_encrypted` 直接拒绝全部加密文件。无打开密码、可以直接阅读的 PDF 也被拒绝。两个入口现在共用 `document_text.pdf_text`，尝试空用户密码，仅对真正需要打开密码的文件返回明确提示。
2. 项目入口要求 `%PDF-` 位于第 0 字节；带 BOM 的实际可读 PDF 被拒绝。现在接受前 1024 字节内的合法文件头，由解析器校验其余结构。提取内容和页码仍保存为原始证据，不伪造 OCR。
3. App 上传使用文件提供者协调读取，先复制到私有目录并核对实际副本字节，再上传。避免用尚未下载文件的零字节元数据直接拒绝。文件协调和复制离开主线程；权限范围在复制期间保持。
4. 个人资料使用相对副本路径，旧绝对路径可按原 UUID 文件名定位到当前容器；上传和移除都使用同一解析方法，避免更新 App 后沿用旧容器路径。复制期间账号变更不会把旧资料并入新身份。
5. 文件选择失败会显示；个人导入错误独立于资料同步，后续同步不再把错误清掉。用户正常取消不报错。原始文件未复制成功时，不声称已经保存。

个人入口仍限单份 25 MB，项目入口仍限 20 MB；PDF 限 300 页、20 万字。真正需要打开密码的文件应先解除密码；无文字层 PDF 给出明确提示，本轮没有新增 OCR 模型或外部接口。
