# CanDid 展示文案

## 产品定位

CanDid 面向销售和面试中的真实沟通，将会前准备、现场记录、复盘与模拟练习连接起来。用户表达自己的疑问和顾虑，Agent 调用相关背景与过往经验，协助完成当前任务。

## 动态记忆：从场景经历到个人经验

CanDid 将长期记忆分为两层。场景长期记忆围绕一个客户、公司或具体事项，持续保存沟通过程、背景资料、目标变化与待办。每次交流都能沿用已有上下文，无需重新交代。

当销售项目或面试结束，场景进入归档。Agent 从完整经历中提炼值得复用的做法、表达和个人认识，沉淀为随用户积累的个人长期记忆。新的场景开始时，这些经验会重新参与准备与演练。

这套机制关注记忆的整个生命周期：内容如何更新、修正，何时归档，以及怎样从一次具体经历中形成可复用经验。与以单场转写、单日整理为主的路线相比，我们希望减少用户再次整理和迁移经验的工作。

## From tool to companion

Candid 希望用户像与熟悉自己的人交流一样使用它。用户说出“明天客户要来，我担心自己还是会讲太多配置”，系统就能结合当前客户的背景与个人积累，组织准备问题和模拟追问。

上下文维护、Skill 选择和工具调用由后台完成。用户无需理解技术配置，也不必反复填表或设计提示词。Agent 根据已有信息推进工作，只在关键缺口上询问，让注意力回到正在面对的人和事情上。

## 与录音、记忆类产品的比较

与 Plaud 等录音产品比较时，我们关注的是一次录音之后的长期价值。转写和总结解决本场内容的整理；CanDid 进一步维护场景的长期过程，并在归档后把经验转化为个人积累。下次遇到相似问题，过去的经历可以直接参与新的准备。

文档式记忆和 RAG 分别擅长保存说明、查找资料。CanDid 在 Launch 后端运行 Agent harness，协调记忆、上下文、任务与 Skill，让资料进入持续的业务流程。比较重点是长期记忆的维护与使用效果；不把竞品未公开的内部架构当作已知事实。

## 与通用 Agent 的比较

Codex、Claude Code 等通用 Agent 提供灵活的任务执行与扩展能力。CanDid 将这些能力组织在沟通场景中：用户提出顾虑，后台选择相关资料和经验，完成准备、复盘或练习。个人用户可以减少组织上下文、选择工具和反复下指令的负担。

完整 harness 为这种体验提供支撑。当前产品由后台管理固定 Skill 与按需加载；用户面向具体任务使用 App，未来的能力扩展也可以沿用这套机制。

## 文本与声音的两条信息通道

规范化转写可能省略重复、填充词与停顿，也难以保留口音和表达卡顿等声音细节。这些信息会影响对沟通状态的理解。CanDid 的双通道方向保留文本的语义分析，同时从原始音频提取表达特征，让两类信息共同参与复盘和长期积累。

录音豆承担现场声音采集，App 与后端负责整理和使用这些信息。停顿、重复与口音需要结合语境分析；口音本身不代表表达能力不足。独立声音分析在本展示中标为概念演示。

## 交付

原生 iOS App 已接通安克录音豆的连接、实时字幕和录音同步，提供会前准备、复盘、记忆库与模拟练习。完整后端已部署到 Launch。
