# 录音说话人认领

2026-10-16。本次为既有录音详情的原生功能扩展，用户可以为录后分人得到的每个说话人编号填写姓名或称呼，并独立标记「这是我」。

## 使用入口

打开录音详情，在右上角更多菜单选择「说话人认领」；也可以切换到「原文」，点击某句上方的说话人标签，进入同一表单并定位到对应编号。没有原文时，更多菜单入口禁用；尚无可认领编号时，表单显示等待录后分人的说明。

表单按说话人编号分区，展示姓名输入框、「这是我」开关，以及该编号的一句原话和时间供核对。姓名可留空。原文优先显示填写的姓名；留空后，本人显示「本人」，其他编号显示「说话人 N · 第 M 段」等原有编号标签。姓名和「这是我」相互独立，填写同名不会自动标记本人。

长录音中，例如 `part0:0` 与 `part1:0` 是不同编号，需要分别认领。同一个人可在多个编号填写相同名字，也可将多个编号标记为本人；系统不会据此合并编号，也不会建立跨录音的声纹身份。

## 保存、版本与失败恢复

- 姓名和本人标记仅属于当前用户的这段录音。提交只携带本次改变的编号；未提交编号保留原有姓名和身份。取消关闭表单，不提交当前草稿。
- 姓名去除首尾空白后使用，最多 100 字；一次最多修改 100 个编号。未改动、姓名超限、修改数量超限、保存中或已有版本冲突时，「保存」不可用。
- 原生端向 `PATCH /v1/recordings/{id}/speakers` 提交 `expected_revision` 及 `speaker_id`、`name`、`is_self`。后端校验编号属于当前录音、编号不重复及请求数量上限；空姓名用于清除该编号姓名。
- 有实际变化时，在事务内生成下一版转写片段，更新录音的 `transcript_revision`、`speaker_names`、`self_speaker_ids` 与 `speaker_identity_status`，并提交对应版本的 `recording_knowledge` 整理任务。旧版片段保留。没有实际变化时返回原版本，不生成新版本或重复整理任务。
- 保存失败时，表单保留填写内容并显示错误。若原文版本已经变化，后端返回 `VERSION_CONFLICT`；表单明确提示尚未保存，提供「放弃本次修改，载入最新原文」。只有成功载入最新原文才替换草稿；载入失败仍保留本次填写。冲突后不自动覆盖最新版本，也不自动重放旧编号映射。
- 保存成功后关闭表单，录音详情重新读取。重新精转写产生新的分人编号时，需要以最新原文重新核对认领。

实现入口为 `ios/CanDid/RecordingUI.swift` 的 `RecordingSpeakerDraft`、`RecordingSpeakerPicker` 与录音详情原文标签，以及 `backend/product_routes.py` 的说话人更新路由。

## 既有设计体系对照

本次沿用 [DESIGN.md](../DESIGN.md) 中的 Warm 浅色体系：米白背景、近白表单行、紫色交互、ink 正文、系统圆角文字与 SF Symbols。编辑器使用原生 `sheet`、`NavigationStack`、`Form`、`TextField`、`Toggle` 和工具栏；输入、开关与动作保留原生交互，姓名输入和标签操作提供至少 44pt 的触控高度。姓名输入可随表单滚动，键盘提供收起动作；保存中显示进度并防止重复操作或交互式关闭。

这是已建立表面的局部扩展，没有新增视觉方向、字体、图片、全局 token 或组件体系。`DESIGN.md` 与 `.impeccable/design.json` 保持不变；未借此修复或重写既有页面的设计差异。原生截图与代码是本功能的依据，未运行仅适用于 HTML/CSS 的网页检测器。
