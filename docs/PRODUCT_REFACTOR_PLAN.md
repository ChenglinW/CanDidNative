# Candid 销售与面试场景改造计划

日期：2026-10-14。状态：首轮功能已实现，软件验证与交付记录见 [首轮交付记录](PRODUCT_REFACTOR_DELIVERY.md)。基线为 master 669a0a0。新版产品方向以用户提供的十三页场景流程与界面草图及随后澄清为准；旧计划保留技术实现与历史证据，产品结构以本计划为准。

首版固定销售 BD 与面试，优先完成销售全流程，再用同一项目页骨架承载面试。项目空间、SOUL、固定隐藏 Skill、记忆适配、Monid、DashScope、录音 SDK、持久任务与恢复继续复用。现有 82 项后端和 11 项 iOS 软件测试是改造前基线，不能替代新功能验收。

## 已确认的产品规则

- 信息层级为我、场景、项目、业务场次；每场包含会前、现场、会后。
- 销售项目对应一项客户机会，多次沟通共同推进；面试项目对应一家公司的一项岗位机会，包含多轮面试。同公司不同岗位或不同机会不自动合并。
- 跨场形成的长期个人发现需要确认，总体尽量减少确认。单场整理、标签及资料关联自动完成；确认支持批量处理，已确认内容复用不重复询问。普通跨场次项目问答不因此增加确认。
- 录音中不刻意禁止问 Agent、查看资料或切换页面；原录音继续，不跟随当前浏览项目变化。文字问答与语音输入都保留，实际音频资源冲突单独协调。
- 实时字幕先显示文字；录后异步分人并补充姓名。没有可靠依据时保留说话人编号，提供一次性集中校正，不由文本模型猜姓名，不默认新增声纹服务。
- 录音文件保存在全局库，可以关联多个项目或场次，也可以暂未关联；没有选项目也能开启录音。
- App 使用原生 SwiftUI，后端继续先在 Mac 本机运行，记忆接口未提供前使用 SQLite 适配。真机安装保持暂停，设备到位后再进行实机验收。

## 已确认的交互与交付范围

| 选择 | 用户确认方案 | 实施要求 |
| --- | --- | --- |
| 归档与跨场确认 | 归档整理自动；已确认事实复用不问；新增跨场个人结论集中确认一次 | 调整 archive_auto 写入规则，保留历史授权及来源；新综合结论进入待确认批次 |
| 客户跟进发送状态 | 邮件系统撰写窗口收到发送结果后更新；微信 WhatsApp 生成分享后由用户一键标记已发出 | 不代发；分享窗口打开不能等同发出，邮件发送结果不等于客户已收到 |
| 提醒与消息来源 | 首页待办和手机本地通知；来自录音、用户聊天或一键更新，暂不接收邮箱微信消息 | 本地通知按系统要求请求权限；缺少新记录只提示核对跟进，不断言客户没回复 |
| 连续对话入口 | 移至问 Candid 页面，保留双击 Candid 头像及明确按钮；各页面输入框保留长按 | 首页顶部用户头像用于个人入口，Candid 头像用于问答与连续语音 |
| 飞书同步 | 首轮完成项目追踪及导出，飞书作为下一阶段接入 | 首轮不依赖飞书权限；下一阶段取得应用权限与目标表格信息后实施 |

以上五项均已由用户确认，以下阶段按这些选择执行。

## 阶段一 统一项目和业务场次

以现有项目空间为上下文与权限边界，将场合信息并入统一项目。保留原 ID 与来源映射，不重建聊天，不覆盖音频或原文；只有已有明确关联或唯一可靠映射才合并，无法判断的旧记录保留并进入待关联列表。

项目增加场景、组织与岗位或机会、阶段与结果、参与方、目标。业务场次增加计划时间、实际时间、轮次或沟通类型、目标、参与者、状态，允许未来场次尚无录音。录音与业务场次分开建模，以关联记录支持多对多引用，标签继续用于发现与筛选。

首页用自然语言创建或补充项目与场次；解析日期时保存时区和来源。用户未给出的日期、姓名或结果保持未知。同名客户或不确定关联只问一项关键缺口，避免生成错误项目。

交付条件：旧聊天和录音可继续读取；可提前建立第三场谈判或二面；切项目、切场次不会混入其他客户资料；一次录音可以关联多个项目且不复制原文件。

## 阶段二 重排页面并建立统一问答范围

底部导航改为首页、项目、录音、记忆库。首页提供全部销售面试筛选、下一场、准备状态及项目列表；原首页底部项目轮播迁为项目页中的场次时间线。项目页共用阶段、参与方、场次和跨场信息骨架，由场景模板提供内容。保留紫色米白圆角品牌，现场录音按草图使用深色专注界面。

建立显式的个人、全部、场景、项目、场次问答范围。页面进入时自动携带范围，问 Candid 显示当前范围并允许更换；首页全部范围不凭空创建一个业务项目。聊天历史、草稿、排队任务和语音请求绑定开始时的范围，范围切换后迟到消息不串入其他页面。

项目问答以该范围的录音及已保存资料为依据，事实回答链接到具体场次、原文和时间点。公司调研在准备流程或明确查询时复用 Monid，结果入库后可供项目问答使用；未查到的资料不能编造成公司事实。

长按输入、发送排队及连续对话继续复用现有执行机制。连续对话入口放在问 Candid 页面，双击 Candid 头像或点击明确的语音对话按钮进入；首页顶部用户头像用于个人入口，各页面输入框保留长按说话。录音中仍可访问问答。把设备数据同步与实时 ASR、手机麦克风采集、播放分别管理，去掉只因 SDK 正在录音就拒绝手机语音的业务限制；同一手机麦克风被临时会议录音占用时，使用统一采集源和有序分发，不另起冲突音频图。技术限制明确呈现，不自动结束会议录音。

交付条件：首页和项目页符合新层级；各页面可以按正确范围提问；录音收起后继续；输入和任务恢复沿用已有规则。

## 阶段三 录音标记与结构化会后资料

接通 SDK 的 markerTimes、markTimeStampList 与 isMark 通知，统一为录音时间轴标记并持久化，支持 App 标记按钮。核对 SDK 时间单位、同步文件偏移、暂停恢复以及重复事件；不假定双击必然有通知，设备端行为需实物验证。异步转写及摘要都引用原始录音时间轴，标记处可跳转回听。

实时保留文字；录后使用当前 Filetrans 分人，补充参与者映射。跨长音频分段的说话人 ID 仍按段处理，不能凭编号相同就认定是同一个人；只有可靠依据才复用姓名映射。

将现在总结与字符串 next_steps 扩展为有来源的共识、问答、承诺、行动、内部进展及资料缺口。每项记录谁、何事、截止时间或待定、所属项目场次、原文位置、来源版本以及是否适合对外。分析未识别本人的全场内容可以形成项目资料，不能自动成为本人经历。

录音原始证据、AI 提取和用户修改分层保存。修订转写后重算受影响资料，旧引用标明已修订；任务失败可恢复，重复执行不生成重复承诺或标记。临时手机完整录音继续只作为开发入口，正式设备入口保留。

交付条件：标记贯穿原文复盘及跟进；行动有负责人和日期来源；未定事项保持待定；录音结束后资料先绑定录音，再供项目读取。

## 阶段四 完成销售会前和复盘流程

销售模板覆盖需求、方案、谈判及成交结果，追踪我方成员与客户角色。会前简报聚合上次之后的真实进展、未兑现承诺、客户问题、口径冲突及本次目标；冲突同时保留两个说法与来源，不自动将最新说法当成最终已批准承诺。

会后复盘关联前场问答，识别重复问题、已补答和仍缺数据的事项。将问题与回答分别存储，保留每次出现的依据，不把同一问题不同场次的证据抹掉。存入 FAQ 是一次明确操作，避免二次确认弹窗。

增加项目问答、承诺、进展和参与者的固定工具，通过现有固定隐藏 Skill 调度；保持一个 Agent 和同一任务事件通路。准备包用结构化内容和来源渲染，不依赖临时拼接整段模型文字。

交付条件：华味销售项目能从前两场真实或明确标记的示例资料生成第三场简报，回答王总关注点，并在第三场后更新问题与承诺。

## 阶段五 客户跟进 内部纪要与项目追踪

从本场资料生成客户跟进稿，支持邮件微信 WhatsApp 的表达格式、自然语言改写和手动修改。对外稿默认只含相关客户会上已讨论的内容，隐藏内部审批、我方短板与未答好问题，不替用户新增报价排期或行动承诺。内部纪要可以包含我方进展和问题，两种版本独立保存，分享前能看清接收对象和实际内容。

邮件使用系统撰写窗口，仅在收到已发送结果回调后更新为已发出；取消、保存草稿和失败不写为已发出，发送结果不表示客户已收到。系统邮件不可用时保留稿件生成与分享，由用户一键标记实际发送状态。微信 WhatsApp 生成或分享后由用户一键标记已发出，打开分享窗口不自动更新状态。保存稿件版本、渠道、相关场次与行动，不自动代发或自动重发。

项目追踪显示阶段、下一步、负责人、期限及结果。行动完成或客户回复可通过一句话更新并保留来源。没有接入消息同步时，系统只知道尚无后续记录，不能证明客户没回复；被 ghost 和丢单由用户明确选择或确认。

导出 PDF Word 图片卡片及文字，默认不带全量原文。PDF 和图片优先用 iOS 原生绘制，Word 用标准文档结构生成；如确需引入新生成库，在实施前汇报具体依赖。原文分享开关由用户主动开启，导出的原文与所选对象和范围保持一致。

首轮提供首页待办和 iPhone 本地通知，状态来自用户聊天、录音或一键更新，不接收邮箱微信消息。更新或删除事项后取消旧通知，防止重复提醒；时间未定的事项不编造截止日期。后端离线时保留已有结果，简报生成显示等待连接，本地提醒不依赖 Mac 全天运行；通知权限未开启时仍提供首页待办。飞书同步列为下一阶段，取得应用权限和目标表格信息后按记录 ID 与版本幂等同步，冲突不静默覆盖。

交付条件：复盘可以生成可编辑客户跟进，内部内容不会混入外发稿；真实发送状态可核对；追踪提醒与导出基于保存记录。

## 阶段六 面试模板与模拟

复用项目场次和准备包组件，按岗位机会组织 HR 业务终面。JD 简历公司情报和已确认个人故事形成准备素材，记录每轮已讲故事、待练问题及有依据的上一轮短板。资料仍走现有上传与 Monid，不增加新模型。

提供故事分配、结果数字提示及模拟一轮面试。模拟单独标为练习，不当作真实面试或实际录音，不计入真实经历、真实场次表现或已被面试官问过的统计。模拟可以使用现有文字和连续语音能力，正式开放连续语音仍需要真机门槛。

交付条件：销售切换到面试保留同一页面骨架；从一面依据生成二面准备包，故事不被自动认作新的真实经历。

## 阶段七 个人素材与跨场发现

记忆库改为我、素材、跨场发现。支持自我介绍版本、FAQ、故事及有依据的个人表达变化；跨场发现保留用到的场次和原文，确认采用集中批次，可逐项修改排除或选择不准确。明确修改用户资料的一次操作就是授权，不再弹出重复确认。

跨场形成的新长期个人结论确认后才作为已确认记忆复用；待确认内容可按候选建议展示，不冒充事实。普通项目摘要和临时跨场问答不用等待这一确认。归档整理自动完成，已有已确认事实复用不再问，归档综合产生的新个人结论进入集中确认批次；既有自动确认记录保留原授权和来源，不追溯伪造人工确认。

雷达图和进步统计必须基于实际样本及固定指标，展示样本数和证据。仅有文本时不推出语气语速或声学打断；数据不足的维度显示暂无依据。草图中的七场五次及图形分数作为明确示例，不能填入真实用户统计。

与负责记忆库的同事约定读取范围、写入候选、确认撤回、来源版本和引用失效的契约。先由本机适配完成产品闭环，接口出现后替换存储适配，不要求 App 直接连接记忆数据库。

交付条件：用户可看到有来源的跨场发现，一次确认成为可复用个人信息，拒绝和转写修订会改变后续检索。

## 阶段八 验证迁移与演示交付

扩充现有离线回归，覆盖旧资料迁移和多录音关联、五种问答范围、跨场确认和撤回、行动日期与版本、内外稿隔离、未知发送状态、本地通知取消、修订引用失效以及任务幂等。UI 测试覆盖首页项目场次切换、长按取消、录音收起问答、客户跟进及面试准备包。保留已通过的字幕语音回归。

软件验证优先临时数据库和供应商替身；新的真实供应商专项先说明当前模型、样本和调用用途，不改现有 demo 金额约定。真机安装按当前暂停状态另行恢复；设备双击标记、音频并行资源、实际录音 ASR 分人及外放打断不能由模拟器测试代替。

六分钟演示按文档先走销售：首页下一场、三场时间线、会前简报、现场录音与标记、会后复盘、客户跟进及追踪，再短暂切面试和个人记忆。演示记录明确区分预置样例与台上实际新录音；没有硬件时保留开发模拟，不称为录音豆实测通过。

交付条件：软件回归与构建结果可复核；完整销售和面试路径可打开；演示数据与真实数据分开；设备与供应商未验收项明确记录，密钥继续只留私有后端配置。

## 依赖顺序与分工

阶段一是所有页面和跨场业务的基础。阶段二和三在共享契约明确后可独立实现；阶段四依赖二三；阶段五依赖三四；阶段六复用一至四；阶段七在来源和确认契约确定后接通，最终由阶段八整体交付。

App 负责导航页面、采集播放、SDK 标记、说话人校正、用户操作、系统邮件与分享、本地通知及展示。后端负责项目场次状态、解析抽取、范围校验、Agent Skills 与调研、来源和版本、跟进稿以及持久任务。记忆同事负责长期存储与检索接口，本轮仍使用本机适配。

首轮已按本计划实施。软件回归、迁移核对、界面复核及推送结果以交付记录为准；飞书和已暂停的真机安装不计入本轮。
