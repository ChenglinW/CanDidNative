# 准备包保存与任务继续修复

2026-10-16。本轮修改后端执行流程，不改变 App 界面或模型选型。手机继续连接原后端，无需重装。

## 确认的问题

实际失败任务显示：普通聊天的四轮执行计数把补问、检索和保存挤在同一预算里，最后一轮禁用工具；恢复时继承旧计数，因此无法推进。另一次 save_preparation 的参数格式正确、来源已读，但模型填写的 user_quote 不在真实用户消息中，被拒绝后又被统一包装成“未找到可访问的资料”。旧成功验收只有信息齐全的直达路径，没有覆盖补问与失败恢复。

## 实现

- 移除固定模型轮数、累计工具调用数和每轮调用数对正常流程的截断；运行配置这些字段使用 null。整体任务固定时长也不再截断有进展的工作；保留单次模型／工具请求超时、上下文窗口、取消和服务并发控制。累计计数继续记账，不代表余额或费用限额。
- 通过连续无进展检测停止循环：重复相同参数且没有新结果、连续工具失败、重复非法协议或只输出未保存报告，连续三轮没有进展时暂停。正常获得新结果可持续执行，显式继续后重新判断进展，保留累计用量和成功步骤。
- 准备意图由当前真实用户任务绑定。user_quote 仅作旧协议兼容，不用于权限或事实依据；虚构引文不能给普通问题授予保存权限。时间、联系人和资料来源的原有依据校验继续保留。
- 参数错误返回字段位置／类型，来源不可用、来源变化、日期错误分别返回可修正原因，不回传用户参数内容或异常堆栈。
- 校验后的报告先保存为内部草稿。存储失败或连接中断时可直接保存草稿；来源被撤回则重新检索，不能复用失效事实。用户被补问后，待生成草稿随新信息重新整理。
- 只有事务完成并回读成功，才发布成功确认。保存已成功但回执丢失时直接找回原报告，不重复写入；保存后不再额外调用模型生成一遍报告。确认文字由服务端生成，语音模式也只播报已保存的结果。
- 所有工作区使用相同完成标准；准备包保存到原空间和原对话。保存事务内加入取消检查，停止先于提交时不发布报告，之后用户可明确继续。
- 显式恢复旧版准备任务时迁移执行策略并重新构建上下文，保留用量和真实补充消息。工作区变化、模型或记忆服务依赖变化仍须重新核对，不能绕过来源权限。

- 准备任务遇到旧长历史的 AI 摘要失败时，降级为有限的真实用户原话片段并保留来源版本，不伪造摘要或记忆；取消、来源变化等错误仍正常中断。

## 验证

最终离线回归 **188 项通过**，结果见 `.build/preparation-tests-acceptance.log`。新增用例使用实际运行时、SQLite、工具执行与任务状态机，模型边界使用可控替身，覆盖：

- 连续十四次模型／工具调用正常完成，超过旧四轮／十二次限制；通用与独立空间均生成报告。
- 多轮检索后补问、用户回答后继续；旧版失败任务及待补充任务显式迁移，历史回答仍在上下文中。
- 参数错误／来源错误的纠正、重复无进展暂停和继续、伪造引文不能授予保存意图。
- 存储失败后的直接保存、提交成功但回执失败时找回同一报告、来源撤回后重新检索、提交前取消与再次继续。
- 长历史摘要失败的原话降级，以及来源变化不可通过降级绕过。
- 未保存的成功声明既不完成任务也不流式展示；连续语音只在保存后提交成功播报。

真实调用与原生界面结果在交付记录补充。早期真实探测曾发生模型网关超时；一次验收提前撞上服务重启返回 502；另一次补问／保存已执行，但界面未定位到较早的报告卡片。这些早期失败不计作通过。最终实现采用保存后直接确认，并为验收补充历史滚动查找。
