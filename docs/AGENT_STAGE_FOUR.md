# 阶段四 任务事件与移动端恢复

日期：2026 年 10 月 14 日。状态：阶段四代码与启动交付完成，功能及异常验收交测试团队。项目卡片与空间模型在四 A 实施；统一录音库、标签和临时手机录音在七 A，正式安克录音豆在七 B。

## 已确认的交互

- Agent 回复中允许发送补充，保存为下一轮独立任务，按同一对话的先后顺序执行。补充不会混入已发出的模型请求。
- 手机断网、锁屏或切后台，只停止客户端观察。后端继续执行，回来查询原任务和遗漏事件，不重新提交模型请求。
- 后端重启后，运行中与尚未开始的队列任务标记为中断，由用户点击继续。等待输入的检查点保留，收到真实答复后继续；不自动重放可能付费的请求。
- 主动停止后保留已生成文字，显示“未完成 · 已停止”，后续模型上下文不采用这段片段，不能将其保留为表达草稿。

用户明确选择补充排队，重启与片段策略由用户授权自行判断后采用上述规则。

## 后端实现

提交任务返回 HTTP 202 及 task ID。输入、队列顺序、轮次、执行 attempt、配置快照、状态、产物和事件存入 SQLite。一个对话只执行一个轮次，不同对话可并行；最多四个执行线程，最多十六个执行/排队预约，等待用户答复时释放线程。当前是单进程原型。

SSE 事件包含 task_id、thread_id、turn_id、attempt、seq、kind、data。事件序号在任务事务内分配并持久化，支持 Last-Event-ID 重放和心跳。事件是带生产者记录的执行日志，不表示用户确认事实；不保存模型 reasoning_content、网关 Key 或原始供应商错误。

| 接口 | 用途 |
|---|---|
| POST /v1/chat/threads/{id}/tasks | 提交下一轮，content 与 client_request_id；返回任务回执 |
| GET /v1/agent/tasks/{id} | 查询原任务、部分文字、输入请求和已接受动作 ID |
| GET /v1/agent/tasks/{id}/events | SSE；after 或 Last-Event-ID 指定已读序号 |
| POST /v1/agent/tasks/{id}/cancel | 以 expected_attempt 停止，重复停止不重复保存片段 |
| POST /v1/agent/tasks/{id}/resume | 显式继续；client_request_id 与 expected_attempt 防止重复执行及过期操作 |
| POST /v1/agent/tasks/{id}/input | 回答 input_id 对应问题；content、client_request_id、expected_attempt；恢复保存进度 |
| POST /v1/chat/threads/{id}/messages | 保留旧同步回执接口，任务在后端独立运行；等待输入时提示使用任务接口 |

事件覆盖 task.queued/running/completed/failed/cancelled/interrupted、text.reset/delta、phase、skill.loaded、tool.started/finished、tools.updated、sources.updated、input.requested。Skill 与内部控制工具对 App 用户透明，界面只呈现文字、业务查询、来源与实际问题。

新增受控 request_input 工具：仅在缺少影响方向的信息且无法继续时暂停任务，保存问题、建议答案及工具轮次检查点。用户可选建议或直接补充文字。普通自然语言追问仍可以普通回答；不能从模型文字中猜测“是否等待”，也不自动选择建议。

完成的工具批次保存消息、来源版本、步骤和已用轮数/调用数。继续前验证原运行依赖和证据；来源已变的恢复检查点会被丢弃并重新准备。模型正在执行的那一段不会被当作已完成步骤。当前查询工具均为本机只读，未接通任何付费抓取或设备动作。

队列中的未来输入在本轮模型上下文与摘要外；下一轮启动后才加入。消息按任务顺序组织，使前一轮晚于补充输入到达的回答仍与原问题对应。消息、事件及最终写入都检查 owner、task、attempt 与当前活动轮次，已停止或过期结果无法提交。

取消信号传到流式模型、摘要调用及工具等待，同时关闭活跃模型连接。当前本机查询为合作式取消，已运行线程可能完成只读查询，返回结果不再进入任务。连接关闭不能证明外部供应商已停止执行或计费，任务保留供应商状态未知的记录。

## App 实现

App 使用新任务接口和 SSE。按后端/访问身份及对话保存事件位置、部分文字、输入草稿、待确认提交与继续/补充动作 ID；Provider Key 不进入 App。重连先查询状态，已确认提交不会重发；继续/补充回执丢失时沿用原动作 ID。

界面支持流式文字、排队内容、取消排队、停止、手动继续、重新发送原问题、等待补充及连接恢复。历史与新对话入口可在后台任务执行期间使用；切换只取消客户端观察，结果留在原对话。键盘输入在运行时提示排队，在等待输入时提示补充后继续。

停止、失败或中断文字保留其未完成状态；不将停止片段当作完整回答或已确认记忆。其他空间的卡片、目标与记忆范围尚未实现，不能把当前按 thread 恢复描述为四 A 已交付。

## 版本与恢复边界

运行版本为 agent-runtime@4，Anker 文本网关流式契约为 anker-chat@2，继续沿用当前已配置模型。旧任务的运行依赖不相同时，继续操作明确报错；原文仍可查看并作为新问题发送，不默默替换原配置。

网关流式能力未通过实际模型调用验证；若未返回合法 SSE，明确失败，不自动再次发起非流式付费请求。Monid 外部 runId 核对、收费请求去重与供应商取消在阶段五接入；本地音频补传与后台录音恢复在七 A/B。
