# Monid 与准备流程修复交付

2026-10-16。运行版本 `agent-runtime@12-research`。覆盖此前五项问题，沿用现有文本模型、Monid 四个供应商端点、工作区隔离、记忆、语音与原生界面。

## 最终行为

1. **准备与调研能够衔接。** 首页与独立工作区统一加载准备流程，可按需搜索、读取正文／字幕，最后调用保存。公司调研流程也能继续保存准备包。删除“调研尚未接通”旧说明，模型实际上下文包含每个 Skill 的精确 inputs 规范，加载错误提供字段级纠正信息。没有 Monid 配置时，普通本地准备仍能使用。
2. **联网要求由服务端核验。** 明确要求先读取指定网址再保存时，必须有本任务实际读取、范围正确且进入准备包引用的 research 来源。不能用本地模板、数据库或空结果冒充对应网页已核实。明确不联网的任务在工具层阻止意外请求；指定网址优先读取，公司档案只在需要具体字段时补充。
3. **业务错误与运行回执分开。** HTTP 403／404 等响应包含有效 runId 时仍保留回执、供应商状态和费用。无匹配返回空结果；不支持来源说明限制；限流及暂时错误可明确继续；不把原始异常或密钥返回模型。Reddit 当前正文供应商明确不支持，正常调用直接说明摘要范围，避免反复付费尝试同站网址。
4. **继续与未知提交恢复。** 确定的临时失败只有在用户明确继续后的新 attempt 才重试；同一次执行重复调用不会重提付费任务。回执未知时先读取 Monid 运行列表与详情，要求供应商、端点、时间范围和输入完全一致且只有唯一匹配，才恢复已有运行。有歧义或未找到不会重新提交。旧 `@10-recovery`／`@11-progress` 的准备及调研失败任务可在明确继续时迁移新策略，保留用量、真实回答及来源范围。
5. **结果、新鲜度和限额。** 无匹配、null、空档案或错误对象不会写成有效公司资料；正文失败明确报错；字幕链接校验视频 ID。搜索缓存一小时、正文六小时、档案和字幕一天，带时间过滤的搜索五分钟；明确最新或刷新绕过缓存，正文传 maxAge=0。重复同任务请求保持幂等，保留原抓取日期和资料范围；缓存复用不重复记费用，跨空间创建各自来源。搜索摘要再次读取仍是摘要。删除 Monid 残留 20 次上限，保留进展判断、请求超时和取消。

工具工作线程同时继承各自截止时间：即使供应商晚回，运行回执可以保留，但超时后的工作不能再发布来源。缓存结果不带不断变化的“年龄”字段，避免重复结果被误判为新进展。

## 验证

### 离线回归

完整后端 **220 项通过**，2 条既有依赖弃用警告。新增专项覆盖：

- 403／404／429／503 回执、无运行 ID 的明确拒绝、网络未知状态、准确恢复与歧义拒绝、显式继续重试。
- 空／错误档案、失败正文、无效视频 ID、Reddit 不重复抓取。
- 跨空间缓存、真实抓取日期、过期缓存、明确刷新、原供应商 maxAge=0、缓存复用不重复费用。
- 连续 23 个不同调研请求超过旧 20 次限制；重复同结果仍能被进展检测停止。
- 两种空间“先读网页再保存”、漏来源被拒绝、跨 Skill 保存、本地准备不受影响、真实模型上下文包含 Skill 参数规范。
- 两个旧运行版本的任务迁移与用户补充保留；晚到回执不发布超时来源。

单元测试使用受控 HTTP／模型边界验证状态与竞态；不将其当作真实供应商验收。

### 实际接口与文本模型

最终按用例汇总 **23 项通过**：14 个真实接口／回执检查，9 个实际 Agent 场景。完整运行中一次问候遇到文本网关 `AGENT_UNAVAILABLE`，没有计作通过，保留原结果；随后只重测该场景通过。较早迭代的百度查询返回空数组，也没有算成有内容，最终用正常查询取得内容。

接口包括 Google、Bing、百度、Reddit／YouTube／微信／B站搜索，强制刷新官网正文，Anker／Stripe 公司档案、PDL 无匹配、真实视频字幕、真实 403 回执。

“回执丢失恢复”使用**真实供应商请求**，仅在客户端收到回执后故意模拟丢失；随后实际查询 Monid 运行记录，恢复相同 ID，整个过程只 POST 一次。它验证真实接口上的恢复过程，不声称真实网络恰好发生过中断。

Agent 验证首页和独立空间的联网准备、离线准备、普通问候、表达润色、单网页、Reddit 摘要降级、视频字幕及最近一月动态。普通表达和离线准备无 Monid 请求；准备包带实际来源且仅保存一份；不必要的公司数据库未调用。
