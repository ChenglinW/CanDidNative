# 长网页读取与动态时效修复

2026-10-16。范围为后端公开资料调研与准备包；不修改 App 页面、设备认证、ASR/TTS、记忆范围或调用额度政策。

## 问题与修复

1. 供应商全文已入库，但模型默认只收到开头 2,200 字。增加精确字符范围、全文长度、续读位置和章节目录；`read_material_part` 支持关键词定位，继续使用真实来源版本及空间校验。目录本身不能作为正文证据。
2. 公司团队、业务、动态等问题对应的未读章节，会在模型准备结束时由服务端通过原有工具执行路径自动补读，再让模型重写。准备包保存也检查相关章节覆盖，不能先保存“未找到”再补依据。无目录或目录不能定位的信息仍需模型按关键词/来源继续查找，未覆盖全文不能宣称全文已读。
3. 实际长文补读暴露工具消息中 `data.items` 和 `sources` 重复包含同一正文，导致上下文溢出。模型消息仅传一份正文及来源引用，客户端事件和最终证据仍保留完整内容。
4. 明确区分 `fetched_at`、`published_at` 和日期来源。默认近期为近 90 天，支持用户指定的相对天/周/月/年范围。已知日/月/年按精度判断，跨越时间边界或缺少可核实日期时标未知，不拿抓取日期或版权年份充当新闻日期。
5. 近期调研要求带时间范围的搜索，正文中近期章节的明确历史/未来日期会触发修订；空结果及有回执的失败允许如实交付，不强迫反复付费请求。年份搜索结果仍须按实际窗口核对。历史职务、规划中功能和商业自述分别标明。
6. 公司团队页中的教授院校任职须核对学校官网；未核对就省略院校和现任头衔，不把合作研究或论文获奖当作产品性能独立验证。

运行时升级为 `agent-runtime@13-reading`，公司调研 Skill 为 `1.5.1`。旧 10/11/12 版调研及准备任务在用户主动重试时可升级，模型和记忆适配配置必须相同。没有数据库结构迁移。
