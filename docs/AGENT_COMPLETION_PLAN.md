ASR 的明确需求是录音时实时显示文字、录后优先准确性的异步处理；最终结果必须提供逐句时间戳和说话人分离，实时阶段无需立即分人。需要覆盖普通话、英语与粤语混合输入，保留粤语原话，复盘可用普通话；录音时长不固定。用户已解除“只考虑安克 SOP 已列模型”的限制，允许评估额外接入 OpenRouter，随后已确认使用阿里云百炼 DashScope 的 Qwen 3.1 Streaming 与 Filetrans；其他模型和新增关键参数仍在接入前确认。

当前 SOP 只列出 HTTP 调用的 `hackathon/v_model/qwen-audio-3.0-asr-flash`，没有第二个 ASR 或实时音频流入口，该型号不支持自动说话人分离。扩展选型分别比较原生流式服务和录后文件转写：OpenRouter 已提供专门 STT 接口及带时间戳和分人的模型，但公开接口仍有文件大小与处理超时限制，不能据模型名称推定支持持续音频 WebSocket。候选能力与费用见 [ASR 两路模型选型](ASR_MODEL_SELECTION.md)，不能默认用短片段 HTTP 轮询替代真正流式，或由文本模型猜说话人。

本机现已用公开的约 1.7 秒普通话示例，完成阿里原生 `qwen-audio-3.1-asr-flash-streaming` 与 `qwen-audio-3.1-asr-flash-filetrans` 最小调用，两路成功。结果见 [调用记录](ASR_CONNECTION_RESULT.json)。这项连通确认不替代后续 App 接入、长录音与三语混说验收，阶段七仍为待开发。

用户后续已明确：通过 DashScope 接入它支持且已确认选用的模型，优先采用官方 SDK。17.6 秒公开英语样例的官方 SDK 首字 2.21 秒、停止发送后完成 11.39 秒；延迟原因未确定，用户决定暂不继续排查。记录见 [官方 SDK 调用](ASR_STREAMING_SDK_RESULT.json)。这项确认不表示 App ASR 管线已接通。

## 项目空间与统一录音库

2026 年 10 月 14 日确认。主页底部、输入框上方用可左右滑动的卡片切换项目空间，最后一张为新建入口。项目空间用于隔离不同沟通方向的 Agent 上下文。例如，同时与两个不同方向的客户沟通，可以分别在两个空间中提问，保留各自目标和历史，避免混淆。

录音统一存放在当前用户的录音库，通过标签关联客户、项目与主题。录音创建无需指定项目空间，当前选中卡片不决定录音标签。一段录音可以关联多个客户或项目，也可以没有关联标签。正式产品的新场录音只使用安克录音豆；设备暂缺时提供临时手机录音入口，设备接通后撤下临时入口。

### 数据关系与上下文边界

| 对象 | 职责与关系 | 第一版规则 |
|---|---|---|
| 项目空间 | 隔离一个沟通方向的目标、对话历史、任务进度与任务摘要 | 点击即建，名称与方向从用户原话生成初始值，可随时修改；按稳定空间 ID 切换 |
| Agent 对话与任务 | 在所属空间中执行并保存历史、配置快照、事件及结果 | 首版每个空间一个默认对话；任务绑定空间及 thread/turn/attempt，重连回到原空间 |
| 统一录音库 | 保存录音、转写和复盘的原始记录 | 每段录音一个稳定 ID；标签可变化，音频文件不按项目复制或移动 |
| 录音标签 | 表达客户、项目、主题等关联，支持多个或没有 | AI 自动生成并生效，标记自动来源；用户可增、改、删 |
| 场合 | 一次沟通的目标和背景 | 可以在空间中作为任务背景；新录音不要求先创建或选择场合 |

项目空间保存一条沟通方向的独立 Agent 上下文。现有 chat thread 仅关联 occasion，需要补充明确的空间上下文关系；客户标签和项目标签分别表示客户身份与沟通方向，录音与资料统一保存。既有记录保留原文和原始字段，增加空间关联时不根据客户名称静默合并历史。

- [ ] 每个空间独立保存目标、消息、输入草稿、阅读位置、任务摘要与活动任务。切换时加载完整的当前空间状态，旧空间的消息、摘要、临时 Skill 输入和事件不能进入新空间。
- [ ] 人格、固定 Skill 和工具代码由各空间共用；模型每轮收到当前空间的上下文。用户通用偏好及通用个人已确认资料仍按既定策略少量检索；与特定客户或项目有关的记忆须符合当前空间范围，其他空间的任务历史不自动加入。
- [ ] 当前空间按相关客户/项目标签和问题检索统一资料，检索结果再按原文内容筛选。标签命中不等于内容已核实；涉及多个客户的录音只提取当前问题需要的片段并标明来源。
- [ ] 用户明确要求跨空间参考时，按指定范围读取并带上来源。标签修改后，新的查询采用新关联；已有报告记录所用来源与标签版本，后续继续任务时重新核对相关性。

### 卡片展示与切换

- [ ] 卡片固定在输入框上方，由用户左右滑动或点击切换，不自动轮播。露出邻卡边缘并显示选中状态，滑动结束后切换上下文；浏览卡片不触发新的模型任务。
- [ ] 展示空间名称、沟通方向或目标、一行最近对话及必要任务状态。显示名称不使用录音场次号、Skill 或 task ID。
- [ ] 最后一张始终为新建空间入口，点击即创建并进入独立上下文；初始名称与方向来自首条有效用户原话，修改入口按需使用。空列表直接展示新建入口；新建空间不自动录音，也不复制旧空间的历史。
- [ ] 切换只改变当前查看的 Agent 上下文，旧空间后台任务继续执行，完成结果留在原空间。停止按钮作用于明确的当前任务；补充排队为下一轮，停止保留未完成文字。
- [ ] 卡片顺序在操作期间保持稳定，后台结果到达时只更新状态。空间较多时可通过历史/空间列表快速定位，新开 App 恢复最近选择。
- [ ] 键盘展开时缩短卡片区域，保留当前空间提示；支持辅助功能切换，沿用温暖版视觉。

### 统一录音入口与标签

### 两段式资料与个人记忆

第一段在录音结束后进行：最终转写与录音绑定，进一步解析为该录音的资料、信息与记忆候选。每条保留 recording/session ID、原文片段、转写版本、AI 生产者和标签。原文证据与 AI 整理分别标记；整理结果可以直接供项目空间读取，无需逐条先确认，也不脱离原录音变成全局个人事实。

第二段在项目空间归档后进行：Agent 分析该空间的目标、用户消息、已完成回答及实际读取的录音资料，提取可复用的个人记忆、资料与信息。用户已选择归档提取后直接成为已确认个人记忆，不增加逐条确认环节。保存归档动作与自动确认策略、AI 提取来源、原空间和原文依据；标记“归档自动确认”，允许后续修改或撤回，不冒充用户逐条人工确认。客户特定信息保留客户/项目标签，检索仍符合当前空间范围；通用个人内容可跨空间复用。

- [ ] 七 A 接入“转写完成 → 录音知识解析”的独立任务，保存与录音绑定的资料/信息/记忆候选；转写修改后标记旧版本并重建受影响知识。解析失败可以重试，原音频和转写继续可读，不重复转写。
- [ ] 阶段六接入归档分析与个人记忆入库任务，先支持已有文字/本人复述及空间历史；七 A 的录音知识就绪后复用同一条提取流程。
- [ ] 归档分析保存处理进度与生成产物 ID，重复归档或重连不重复入库。归档空间仍能查看、恢复；原始资料保留，恢复不偷偷删除已提取个人资料。
- [ ] 与同事扩展确认权限与字段，支持用户授权的归档自动确认，保留 AI 生产者和策略依据。当前仅允许人工 actor 的 L3 写入规则需专门扩展；不通过伪装人工操作绕过现有规则。

### 助手交互原则

用户尽量通过正常聊天表达目标。新空间不必先填名称或方向，常规资料整理、录音标签和已授权的归档提取自动执行，显示结果与来源并允许修正；只在缺少会影响执行方向的信息时追问。资料分类和更改名称作为按需入口，不把每一步拆成确认弹窗。模型、供应商和费用等开发选择仍按开发前约定确认。

- [x] 增加归档、归档列表及恢复，归档后仍可读取历史；保存归档自动确认策略，准确显示自动整理尚未接通。
- [x] 阶段六已接通归档自动学习；七 A/B 的独立录音工具栏、全局状态及设备回调已接线，实物未验证。

交付条件：空间、卡片、新建、严格范围及归档/恢复代码通过编译并能启动；功能、空间串用、读取范围和切换异常由测试团队验收。自动知识解析和归档提取按后续阶段交付，不因本轮有归档按钮而标为已完成。

## 阶段五 资料输入和公司调研

- [x] 支持用户提供文本、链接和 PDF 等第一批资料；保存原文件、提取文本、页码或片段位置。无法解析的文件明确报错，不由模型猜内容。
- [x] 在后端建立 Monid HTTP 适配器，为 Skill 提供网页搜索、正文读取和公司档案补全工具。Search1API、Firecrawl、PDL 是当前候选，Exa 和 Apollo 是替代候选；汇报实际可用性、覆盖范围与费用后，由用户确认首批供应商、端点和预算。每类先接一个供应商，复用 Jupiter 搜索后读取及限制页面数量的机制。

- [x] 将 Monid 异步 `runId` 绑定到 Candid 任务，由后端查询并保存结果，App 回到前台继续读取同一任务。恢复时先查询已有运行，避免重复提交付费抓取；同时检查任务状态和 `providerResponse.httpStatus`，不能把 `COMPLETED` 一律当作成功。外部任务取消能力需另行核对，App 停止等待不能标为供应商已停止执行。
- [x] 公司调研先确认公司身份，再围绕官网、业务、产品、近期公开信息与本次沟通目标开展多次搜索。
- [x] 在基础调研可用后，按场景增加 LinkedIn 公司动态、公开招聘岗位、Amazon 或 Reddit 产品评价和 YouTube 字幕。客户沟通优先公司动态与产品反馈，面试优先岗位信息；限定时间范围和样本量，不由少量评论推断整体口碑。

- [x] 报告包含结论、来源 URL、读取日期、相关摘录、冲突或未确认项，区分直接来源与模型推断。
- [x] 报告引用稳定资料 ID 与片段 ID，后端校验引用属于当前用户可访问且实际取得的资料。标明搜索摘要、已读取正文和公司数据库结果；不存在的引用返回修复或未确认状态，不展示为有效来源。
- [x] 公开网络资料跨来源调研；登录、付费或私密平台仅在对应授权和连接可用时读取，报告说明覆盖范围。
- [x] 保存调研报告为场合资料；公司公开资料不能混入用户个人经历或已确认表达。
- [x] App 展示真实阶段进度、可打开的来源、报告与后续准备入口。用户能补充资料并继续原任务。

交付条件：输入公司和沟通目标，可得到基于实际读取资料的报告；资料不足、公司重名和来源冲突不会被静默忽略；后续准备可引用该报告。

Monid 是本阶段的外部信息入口。人格、Skill 流程、资料判断、报告生成和记忆确认仍由 Candid 编排；现有文本模型接入保持可用。ASR 可评估安克之外的原生服务或 OpenRouter，实际组合确认后接入；TTS 型号和音色仍待用户确认。第一版通过后端 HTTP API Key 接入 Monid，用户在 App 内无需另行登录 Monid；以后若让用户使用自己的 Monid 账户和余额，再评估 OAuth。CLI 和 MCP 不作为手机运行依赖。

| 顺序 | 开发内容 | 可观察的交付结果 |
|---|---|---|
| 五 A | 用户资料模型与输入解析，不依赖 Monid | 可以保存和解析用户文本及可解析 PDF；链接可先保存为待读取资料 |

## 阶段六 准备和复盘的文本流程

依赖：阶段二、三、四及五 A 的用户资料输入。五 B 至五 D 完成后增加自动调研资料，五 E 的平台扩展随后补充。

## 阶段七 ASR 和设备输入

七 A 依赖阶段四、六，完成统一录音库、文件管线、临时手机输入及标签；七 B 依赖七 A，完成正式安克录音豆输入。设备暂缺时用手机验证开发流程，完整交付必须完成七 B，正式新场录音入口只使用安克设备。阶段八可先开发编排，正式语音输入渠道在实现前另行确认。

### 七 A 文件和手机录音

- [x] 接通主页独立工具栏中的临时手机“开始录音”：权限与必要确认后创建无强制客户/项目归属的新场次，提供全局时长、结束与返回入口；滑动项目卡片不改变录音，重复点击不创建第二场录音。
- [x] 最终转写后解析成与该段录音绑定的资料、信息和记忆候选，供项目空间按范围读取；原音频、转写与解析产物保持版本和片段关联，修改转写后重建受影响内容。
- [x] 统一录音库及标签接口支持 AI 自动生效、人工增改删、多客户/项目标签或无标签；使用现有文本模型基于最终转写生成，人工决定优先，检索和后续上下文跟随标签修订。

- [x] 比较现有安克 ASR、原生实时/文件转写服务和 OpenRouter STT 候选，按实时文字、录后分人、逐句时间戳、中英粤语混合及粤语原话需求汇报功能差异、费用、超时与长录音处理成本；用户确认组合后再接入，不自行降低交付要求。
- [x] 实时音频一路进入流式 ASR 显示可修订字幕，同时完整保存原始音频；实时的阶段结果与最终文件转写分别记录。录音停止后提交独立异步 ASR 任务，最终转写作为复盘和记忆草稿的默认依据，保留模型、版本和人工修订来源。
- [x] 为实时输入处理连接恢复、音频片段序号及已发送范围；不以未发送的音频伪造连续字幕。恢复实时连接与录音文件补传分开处理，最终文件仍可进入异步流程。
- [x] 核对选定 ASR 渠道的协议、请求头、音频格式、采样率、长度限制和返回结构，现有评估适配器只作代码参考，不作为生产选型结论。
- [x] 增加开发期临时手机麦克风录音：权限说明、系统音频会话、录制结束落盘、来电等打断处理；录入结果进入统一录音管线。通过配置管理临时入口，七 B 完成后撤下正式 App 中的手机新场录音入口。
- [x] 后端按实际模型要求解码、重采样和分片长录音，保存原音频偏移，拼接时去除重叠重复。当前参考适配器要求 16 kHz 单声道 PCM16 WAV、不超过 5 分钟；设备同步后的 M4A 不能直接按此输入。
- [x] 长录音按选定模型和接入渠道的单次限制分段，记录全场时间偏移，避免重叠片段重复；不能把单次限制当作产品录音上限。跨段说话人对应需按实际分人结果设计，标签不确定时保留待确认状态，不生成虚假的 `speaker_id`。原生模型允许长文件不代表 OpenRouter 转发接口具有相同时长和超时条件。
- [x] 本地音频或手机录音进入后台处理任务：上传校验、转写、结果保存、总结、复盘和记忆草稿。
- [x] 按用户确认的时间精度设计转写和证据结构。当前参考适配器只提供音频片段边界；若需求是逐句时间戳，选用满足需求的模型或补充对齐能力，不能自行降低为片段边界交付，也不能伪造逐句时间戳。
- [x] 未知说话人进入归属确认；获得相应授权的全场文字可用于会话总结，个人经历与表达草稿仅引用已确认本人片段。不能从设备通道推断本人，无法确认时可以生成注明限制的总结，暂不生成归属于用户的记忆。调整现有只读取 `self` 的复盘入口以支持这两种用途。
- [x] 支持转写修正及修正版本，复盘和来源跟随所采用的版本。无录音同意时不使用他人话语。
- [x] 将上传与 Agent 执行分开记录：文件上传并确认入库后才启动后端处理任务。上传中断时保存本机文件，回到前台核对服务端接收状态后续传或安全重传；第一版允许前台上传，不承诺后台同步始终持续。
- [x] 手机保存尚未同步完成的音频；服务端确认完整接收后按保留策略处理本地副本。

交付条件：采用已确认模型，文件或临时手机录音进入统一库、转写、自动/手动标签、复盘与草稿流程；符合时间精度与说话人要求，标签支持多关联和无关联。未知说话人的总结与个人记忆生成分开处理，上传中断不会丢失本机文件。手机新场录音为开发替代，正式设备渠道由七 B 交付。

### 七 B 安克录音豆与正式录音入口

- [x] 正式新场录音只通过安克录音豆；将统一工具栏入口接到设备能力，撤下临时手机录音入口。无设备时提供连接/授权入口，并可继续查看既有统一录音库，不静默改用手机录音。

- [x] 复用现有安克 SDK 封装，处理授权、扫描、连接、设备状态、文件同步和 Opus 转换。
- [x] 核对目标设备是否能在录音过程中通过 SDK 输出音频、片段顺序与编码格式，再衔接实时字幕。当前 App 的音频片段回调尚未接通，回调存在也不等于已验证实时取流；设备实时字幕仍是本轮需求，不能仅用录后同步替代。手机麦克风实时路径可先完成。
- [x] 设备文件使用稳定 ID 防止重复导入，进入与手机录音一致的后端流程。
- [x] 把 SDK 授权资料、设备、真机和模型凭据作为外部依赖，提前准备。设备开始和停止方式遵循 SDK 实际能力，App 展示准确提示。
- [x] 补充后端到 App 的安克设备动作请求与回执，只开放已实现的动作；动作在手机上校验权限与设备状态。设备控制与手机 TTS 分别交付。

交付条件：正式新场录音入口只使用安克录音豆，临时手机入口已撤下；设备音频进入统一录音库、标签和 Agent 复盘流程，可按真实片段范围回看原文，已实现的设备动作有执行回执。SDK 的业务衔接与错误状态完成后交测试团队用真机和设备验证；模拟器运行不替代硬件验证。

## 阶段八 TTS 和轮次式语音 Agent

依赖：阶段四、七 A；TTS 编排可先进行，正式语音输入渠道与安克设备职责在实施前确认。七 B 是正式新场录音交付的必要依赖。

- [x] 先向用户汇报并确认 TTS 模型、渠道、音色、语言、费用与延迟要求，再实现接入；统一格式、采样率和返回音频生命周期。
- [x] App 支持播放、暂停、停止，处理系统音频打断和耳机变化。
- [x] 按已确认语音形态实现交互。当前候选为明确轮次：用户语音输入、ASR、Agent、TTS；输入来自设备还是另有正式语音消息入口，实施前确认，不将临时手机录音入口默认保留。文字与语音在选中项目空间共用任务和历史；实时交互需求确认后修订方案。
- [x] 播放时避免把回答再次录入 ASR；用户重新讲话时停止播放，并明确是否取消正在生成的旧回答。
- [x] ASR、Agent 或 TTS 任一阶段失败时保留已完成结果，允许文字继续。
- [x] 根据用户需求和已核实的模型渠道能力，共同确认流式语音、自动端点检测与双向打断的范围；不能由 HTTP 音频接口推定支持，也不能未经确认将必需能力后置。

交付条件：达到用户确认的语音交互形态，用户可以用手机语音完成准备或追问；回答可以播报并停止；语音失败时能继续文本对话。安克设备动作及回执随七 B 交付。

## 阶段九 完整流程交付和迁移准备

## 执行安排

主要顺序：一 → 二 → 三 → 四 → 四 A 主页卡片 → 五 A → 六文本流程 → 五 B 至五 D → 六调研增强 → 五 E → 七 A → 八 → 七 B → 九。

阶段四的任务基础可与阶段二、三同时开发，合并后再做公司调研。手动开发默认按表中顺序逐项推进。SDK 授权、设备、Monid 凭据与费用上限、语音网关参数在阶段一就开始准备，不让外部依赖阻塞后面的集成。每一阶段先交付可运行的小流程，再进入下一阶段。

| 顺序 | 你当前要完成的工作 | 完成后具备的能力 |
|---|---|---|
| 1 | Agent 模块拆分、工具注册、接口约定 | 现有文本 Agent 可继续扩展 |
| 2 | `SOUL.md`、Skill 索引与按需加载 | 人格可配置，业务流程可通过 Skill 接入 |
| 3 | 记忆适配、证据读取、上下文摘要 | 新对话可复用确认资料，长任务保留目标 |
| 4 | 任务持久化、事件、重连与取消 | 手机切后台后能找回任务 |
| 4 A | 独立项目上下文、主页卡片与最后新建入口 | 不同沟通方向各自保留历史和进度，任务不串空间 |
| 5 | 五 A 的用户资料输入 | 使用真实文本或 PDF 作为准备资料 |
| 6 | 沟通准备、复盘、归档分析与个人记忆自动提取 | 文本资料完成业务流程，归档知识自动入个人资料层 |
| 7 | 五 B 至五 D 的 Monid 接入，并增强阶段六 | 自动获得公司报告并用于沟通准备 |
| 8 | 五 E 的公司动态、岗位与产品反馈 | 调研根据沟通场景选择平台信息 |
| 9 | 七 A 的统一录音库、临时录音、ASR、标签与录音知识 | 录音解析成绑定原音频的知识，供空间读取 |
| 10 | TTS 与轮次式语音交互 | 用手机语音调用同一套 Agent 与 Skill |
| 11 | 七 B 的安克录音豆接入与入口替换 | 正式录音只用设备，临时手机入口撤下 |
| 12 | App 状态完善、交付文档、迁移配置 | 形成可交给测试团队的完整 Agent |

若 Monid 凭据或端点不可用，继续完成用户资料、文本流程和七 A、阶段八的可开发部分。安克设备暂不可用时，用临时手机录音开发统一管线；设备接入是正式录音交付的必要部分，不能用手机替代标记完成。自动公司调研和设备接入均需按各自条件交付。
