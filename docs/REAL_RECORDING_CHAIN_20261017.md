# 真机录音完整链路验证（2026-10-17）

主数据链路已跑通；原生截图曾发现声学指标接口的云端版本缺口。后续该接口已经发布，2026-10-17 的独立 HTTPS 复核通过，见文末跟进。

本轮使用上一轮从连接 iPhone 的 Candid 中复制的真实录音，调用实际云端接口和已配置模型。测试数据属于独立临时账号，没有写入手机原账号；没有替换成合成音频或模型替身。

## 输入与结果

- 原录音：172.785 秒，单声道 16 kHz AAC，725,118 字节。
- 上传前、回执、下载回听文件的 SHA-256 一致：`cb5969a615c6f40dd8aae6fd6b50dcd1ab30f426af4f27e5a03703f61c21ae85`。
- 识别主题：UI 设计审美分歧；真实精转写模型为 `qwen-audio-3.1-asr-flash-filetrans`，复盘生产者为 `anker/deepseek-v4-pro`。
- 50 段逐句原文、3 个自动说话人。用户明确确认说话人 `part0:1` 为本人后，生成第 2 版原文：9 段本人、41 段其他人。认领仅改变身份归属，50 段的文字、时间与原说话人 ID 均保持一致。
- 本人有效句段时长 23.64 秒；语速估计 304.6 字词／分钟，说话占比 17.1%。占比以全场有效说话时长 138.44 秒为分母；指标依赖自动转写和分离质量，不是声学校准成绩。
- 原始音频提交完成至首次记忆提取结束约 24.70 秒，其中精转写约 10.30 秒、首次复盘约 12.81 秒；均为本次样本耗时。

## 新发现及本地修复

真实追问的引用同时出现同一素材的 `faq:<id>` 与旧 `asset:<id>`。资料检索的补充路径遗漏了旧副本过滤，可能让用户编辑后的旧文案继续进入 Agent 上下文。

已在 `backend/tasks/materials.py` 的 `Materials.search` 中排除存在 canonical 映射的历史原件，归档后也不会回退读旧副本，未导入的独立素材继续可检索。新增回归先复现失败，再修复通过；相关 FAQ、资料、复盘和标记回归共 **65 项通过**，2 项现有依赖弃用警告。

本次云端真实账号的数据已导出到私有本地目录，用同一查询分别执行修复前后的检索：修复前同时有 faq 与 asset；修复后只保留新版 faq，文本与刚保存的修订一致。该修复**尚未部署云端**。

### 表达页新接口未部署

原生截图 `native-screenshots/0C2ECAF3-8F65-45E2-9CA5-3646122D05A9.png` 中，304.6 字词／分钟正确显示，但其下有红色 `NOT_FOUND：请求不可用`。当前本地新版 `MergedDeliveryPage.refresh()` 每 5 秒请求 `/v1/library/metrics`；该接口属于工作区同时新增的声学指标功能，云端缺少对应能力。

自动化验证检查了回放、原文、原有语速和保存文案，均通过；它没有断言全页不存在错误提示。人工复查截图发现上述问题后，最终结论已修正为“主链路完成，仍有版本对齐缺口”。这处尚未修复或部署，不能把新版声学停顿／音高功能计为本次真实云端通过。

## 质量与测试边界

转写保留了口头重复，也存在明显生硬片段；未逐句人工听写标注，不能报告识别错误率。自动分离的三个 ID 不代表每句身份都已人工校准。录音内容实际为产品讨论，本例的销售场景标签仅用于功能验证。

中途验证脚本曾把已标为“依据变化”的历史条目也要求匹配当前修订的片段，导致断言失败；修正为分别校验当前引用与保留的历史引用后通过。原音、原文和云端任务没有因此重复提交。检索回归中也遇到并行工作区其他改动带来的短暂失败，保留其实现后重新运行通过。
