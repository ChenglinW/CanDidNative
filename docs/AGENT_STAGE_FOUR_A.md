# 四 A 项目空间与主页卡片

日期：2026 年 10 月 14 日。代码、编译和本机启动交付完成，软件功能与异常验收由测试团队负责。

## 用户已确定的行为

项目空间代表一个沟通方向的独立 Agent 上下文。卡片位于主页输入框上方，左右滑动稳定后或点击切换，最后一张始终是新建入口。新空间点一下即可创建并聊天；名称与初始方向取自首条有实际内容的用户原话，没有额外模型调用或必填表单，之后可以按需修改。

同一空间使用一个默认对话，独立保存目标、消息、任务、摘要、草稿、阅读位置和事件恢复位置。人格、固定 Skill 和通用回答偏好共用；项目目标随空间，不从全局偏好载入其他沟通方向。切换空间只停止手机观察原任务，后台继续执行。

旧对话逐段独立迁入，沿用标题，并从原用户消息设置初始方向，不合并历史。未标明资料范围的旧记录不会自动进入 Agent；仅关联当前空间或明确标为通用个人资料的内容可读取。

## 后端

新增 project_spaces 和 agent_source_scopes。空间拥有稳定 ID、默认 thread、名称、方向、版本、独立上下文版本和归档状态。原有 thread/task/summary 增加空间关联，任务配置冻结本轮空间目标；显式修改目标时要求先结束当前活动/排队任务。

新建使用 client_request_id 幂等，编辑与归档使用 expected_version，资料范围修改使用 expected_revision。旧对话迁移在启动时完成且可重复执行，不产生额外对话、消息或模型调用。

| 接口 | 用途 |
|---|---|
| GET/POST /v1/project-spaces | 列表与点击即建；name、goal 可省略 |
| PATCH /v1/project-spaces/{id} | 按需修改名称和方向 |
| POST /v1/project-spaces/{id}/archive | 归档完成的空间，保留历史与策略 |
| POST /v1/project-spaces/{id}/restore | 恢复归档空间 |
| GET /v1/project-spaces/{id}/materials | 用户查看可关联的真实资料 |
| PUT /v1/agent/material-scope | 未分配、一个/多个空间、通用个人资料之间调整范围 |

Agent 的自动检索、搜索工具、场合列表、录音列表、指定 ID 原文读取、来源版本检查及摘要恢复均使用服务端绑定的 workspace_id。模型参数不能选择另一空间或扩大范围。App 用户仍能浏览自己的统一资料库，并通过“可读取的资料”明确关联内容。

资料范围保存于独立元数据，不修改原始音频或不可变证据。关联修订参与来源版本，移除或修改关联后，旧引用与恢复检查点需重新核对。新聊天保存的表达草稿默认关联生成它的空间，仍不自动成为长期已确认记忆。

运行版本为 agent-runtime@4A，记忆适配草案为 candid-memory@3-draft。旧运行依赖不同的未完成任务仍只能作为新问题发送，历史保留。

## App

卡片显示名称、方向和业务状态，顺序固定按创建顺序，不因后台更新移位。滑动停止后加载上下文，点击和辅助功能也能切换；键盘展开时缩短卡片。空间列表提供快速定位、归档列表与恢复。

首次/最后的新建入口不弹必填表单。新建回执丢失时沿用原请求 ID；输入、阅读位置和当前选择按对话与后端身份保存，旧请求与事件不能覆盖新选择。阅读旧消息时避免流式文字强制滚到底部。

“名称与方向”和“可读取的资料”在菜单中按需使用。归档后隐藏于主页活动卡片，但可从列表查看原历史；活动任务未结束时不能归档，归档空间需恢复后才能继续发消息。

## 两段式知识与归档

已加入完成计划：录音结束后，先解析为仍绑定该录音的资料、信息和记忆候选，供项目空间读取；项目归档后，Agent 再分析整个空间并提取可复用内容进入个人资料层。

用户已选择归档提取后自动成为已确认个人记忆，不增加逐条确认。后续实现必须保留 AI 生产者、原文、原空间、归档策略依据与“归档自动确认”方式，不能冒充逐条人工确认。客户特定内容保留范围/标签，通用个人内容可复用。

本轮实现了归档/恢复状态和策略记录，尚未实现归档模型分析、自动个人记忆入库或录音知识解析。界面显示自动整理暂未接通；能力接口也返回 false。归档分析与确认权限扩展安排在阶段六，录音解析与标签安排在七 A，正式录音豆在七 B。当前 SQLite 的人工 L3 写入保护没有被绕过。
