# 记忆库与问题归类 · 2026-10-16

> 最新：Qwen3.8-Max 回退经单变量对照未提升 F1，生产已回到纯向量基线；见 [回退对照结论](MERGE_CONTROL.md)。本文的 72.15% F1 即当前生产策略的结果。

## 已接入

- 记忆库使用用户提供的 `docs/references/candid_memory_me_tab_sales_prototype.html`，原生 SwiftUI 实现「我 / 素材 / 跨场发现」。保留暖纸底色、白色描边卡片、紫色发现卡、实色页内分段。
- 「我」呈现表达入口、已有本人改写应对的问题数、录音复盘提到下一步的场数、跨场发现。大字体下统计卡改为单列。
- 「素材 → 客户问题」显示语义合组后的问题，支持搜索所有原始问法、查看每次应对、修改成自己的说法、按时间跳转录音原文。长期资料上传、重试、移除及原有表达积累保留。
- 「跨场发现」保留依据、单条确认、纠正和批量确认。旧来源会显示已修订状态。

## 生产归类策略

`qwen3.7-text-embedding` → 单位向量 → 余弦 Top 15 候选边 → 按候选边得分排序 → 跨组平均相似度达到 **0.6646** 才合并。

该实现复现既有 benchmark 的候选边平均合组规则，非全局贪心 HAC。相同分数用固定顺序打破平局，未使用 reranker。以每个账号的当前、可访问、非练习、非示例的「客户常问」表达为输入，用其逐字问题引用生成向量，不用 AI 建议的回答生成向量。新复盘提示词要求此类引用必须是客户实际提出的问题；历史条目仍沿用已提取的引用。

- 录音复盘完成后排队归类。打开记忆库也会补排已有资料，已有账号无需手动迁移。
- 所有模型调用在现有持久化后台任务内执行，不在页面读取请求或数据库事务内等待网络。
- 按账号、模型、文本哈希缓存向量；只编码新增文本；批次成功后缓存，失败可以继续。
- 每次提交前重新校验来源快照。原文修订、撤回或删除后，旧分组不再展示；归类未完成时展示未合组条目和进度／重试入口。
- `question_embeddings` / `question_groupings` 随账号记忆删除一起清除。页面刷新只读取缓存元数据，不反复解析全部向量。
- 增加依赖 `numpy>=1.26,<3`。使用现有 `DASHSCOPE_API_KEY`，通过现有业务任务 worker 执行。

## 验证

- 后端相关测试 **69 项通过**：候选召回、平均合组防止链式误并、持久化、缓存复用、跨账号隔离、来源失效、模型请求期间修订、全部来源移除、恢复重排、失败重试、HTTP 返回及真实录音统计；包含既有 Companion / Product 回归测试。
- 生产代码直接重放缓存的中文译文测试：199 问，55 组，pair precision **63.22%**、recall **84.00%**、F1 **72.15%**；与原 benchmark 完全一致。额外 184 问 F1 **74.10%**。
- 实际 Qwen3.7 服务 + 临时数据库 + 业务任务验证：两种询价问法合为一组，交付时间问题单独成组。使用三条合成问题，无真实客户资料。
- iOS 模拟器编译及 UI 验证：常规／最大辅助字号、三页签、同组多条问法、应对编辑、表达详情、跨场发现与批量确认。2 项 UI 测试通过；最终测试包与截图记录在本文末尾。

## 与示例原型的明确差异

原型声明数值是示例，部分评分规则待校准。现有生产管线没有去静音后的发音时长、句中停顿、可靠口头禅计数及校准后的五轴分数。因此本次**没有实现或展示雷达分数、趋势线、最弱项判断**，表达入口和五维详情展示待积累／待校准状态；说话占比可展示已认领说话人的句段时长估算，并注明静音、重叠说话的影响。即使满 3 场录音，也不会凭空生成分数。

原型「异议有确认的应对」改为已有真实数据支持的「问题已有我的说法」；「拜访约定了下一步」改为「录音复盘提到了下一步」，不把模型提取的后续事项当成已确认承诺。原型的客户数、客户姓名和示例叙述不进入真实账号。

F1 来自通用问句译文测试，不代表销售实录已达到同等效果。当前是账号内精确向量搜索和全量合组，适合当前小型记忆库；尚未验证大规模题库吞吐。归类按已抽取的客户问题工作，不代表从每段录音穷尽所有问题，也不自动改变原有应对内容。旧 V1 项目页的 `question_key` 跟踪未改动；本轮接入的是当前 V2 记忆库与录音复盘流程。
