# Qwen3.7 向量 + Qwen3.8-Max 回退

> **未采纳。** 后续单变量对照证明此回退不提升 pair F1，生产已回到纯向量基线。本文件保留当时的实现与验证记录，供参考。结论见 [MERGE_CONTROL.md](MERGE_CONTROL.md)。

2026-10-16。本地实现与真实接口验证完成，尚未部署到线上服务器。

## 当前行为

1. 复用已有 `qwen3.7-text-embedding` 向量缓存。
2. 按问题文本固定顺序重建分组，保证数据库随机 ID 不影响处理顺序。完全相同的文本复用已有归属；第一条问题直接建组。
3. 对其余问题召回已处理问题的 Top 15，形成候选组；用新问题与候选组**所有成员**的平均余弦相似度选出最接近的组。
4. 最高分 ≥ `CANDID_QUESTION_AUTO_THRESHOLD` 时直接归组。默认 **0.85**，允许配置 0–1，改配置后需要重启后端。
5. 最高分 < 阈值时调用 **`qwen3.8-max`**。输入为新问题及候选组的全部不重复问法；模型选择一个候选组，或返回 null 作为新问题。提示词要求相同信息需求，区分否定、对象、条件和时间，不因话题相同而强行合并。

接口返回 `score_type: cosine_similarity`。这里没有校准概率，也没有把 0.85 称为 85% 正确率。旧的 0.6646 是旧算法的合并阈值，不能当作这套回退策略的置信概率阈值。

当前是顺序归组策略，保留组内平均相似度规则；与旧的候选边平均合组算法不完全相同。已有组不会因为后续一条“桥接”问题而自动整体合并，也不会由大模型重新拆分高分自动归组。Top 15 未召回的组不能被本次模型判断选中。

## 接口、缓存与失败处理

- 通过既有的 Anker OpenAI 兼容网关调用，端点 `{ANKER_AI_BASE_URL}/chat/completions`（默认 `https://ai-router-cn-pub.anker-in.com/chat/completions`）。模型 id 由 `CANDID_QUESTION_FALLBACK_MODEL` 配置，默认 `hackathon/v_model/qwen-max`（即 qwen3.8-max）；关闭思考（`enable_thinking:false`）、JSON 输出、最多 256 输出 tokens、60 秒请求超时。此前直连 DashScope `/compatible-mode/v1` 的写法与地域映射已移除。
- 共用服务端 `ANKER_AI_API_KEY`（与文本 Agent 同一网关密钥，仅存服务端）。手机端无需模型密钥或额外依赖，现有记忆库接口兼容新增元数据。
- 请求不持有数据库事务；返回后重新核对账号、任务状态、原文版本。未知组 ID、截断或格式错误的响应均拒绝。
- 用账号 + 模型/提示词/阈值版本 + 完整语义输入缓存判断。缓存只保存输入哈希、问题文本哈希和组选择，跨账号不复用。来源不再有效时清理对应缓存，删除记忆时一起清除 `question_judgments`。
- 模型失败时任务显示失败并可重试，页面保留原始问题，不宣称已经完成归类。已成功的向量批次与模型判断可在重试中复用。
- 单次候选输入超过 100,000 字符时明确失败，不静默截断成员。每条不确定问题最多调用一次大模型；没有无限自动重试。
- 归类快照保存每条判断的方式和相似度；任务结果记录新模型请求数、判断缓存命中数。阈值或策略版本变化会自动产生新任务。

## 验证结果

**81 项后端测试通过**：高分跳过模型、低分合组／新建组、平均相似度而非最近成员、全部组成员送审、重复问句、严格响应校验、缓存与账号隔离、删除、模型调用期间来源变更、失败重试、既有业务回归。

真实完整后台链路的四条合成问题：两种询价问法合成一组，交付时间与按月付款各一组。调用大模型 2 次，向量直接归组 1 次，第一条建组 1 次。

### 中文小样本对照

从既有中文译文 **test** 集按固定哈希抽取 8 个多问法组（每组 3 条）及 8 个单例，共 **32 条、16 个标准组**。标签只用于抽样覆盖和评分，不传给模型。阈值预先定为 0.85，没有使用这批 test 标签调参。这只是小样本冒烟比较，不能替代完整测试或销售实录验证。

| 方法 | Pair Precision | Pair Recall | Pair F1 | 归类耗时 |
|---|---:|---:|---:|---:|
| 原纯向量平均合组（0.6646） | 71.43% | 62.50% | 66.67% | 0.011 秒 |
| 向量 + Qwen3.8-Max（0.85） | 100.00% | 50.00% | 66.67% | 31.071 秒 |

两者均使用缓存向量，**耗时不含 embedding API**。回退有 26 次真实模型调用、0 次判断缓存命中，平均每次 1.194 秒；其余为 3 次向量归组、2 次完全相同文本复用、1 次首组创建。新方法只有 12 对预测同组，12 对都正确；样本量很小，100% precision 不可推广。

结论：这一轮减少了误合并，但增加了漏合并，F1 没有提升，首次处理更慢。默认 0.85 是可配置初值，**不是已优化的上线参数**。后续若优化阈值，应在训练／验证集上选择，再独立评估完整测试集，不能在这批 test 上反复挑最高值。

复现脚本：`scripts/benchmark-question-fallback.py`；结果及样本 ID：[hybrid-smoke-results.json](hybrid-smoke-results.json)。原纯向量全量中文译文 F1 72.15% 不适用于新策略，也不能与这 32 条子集的分数直接比较。
