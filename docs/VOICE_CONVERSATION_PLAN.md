## 用户已确认

- 长按主页输入框开始说话，松开自动发送，上滑取消。
- 双击左上角 Candid 头像进入连续对话。短暂停顿继续听，约 1 秒停顿后自动发送，可以立即接着补充。
- 用户在 Candid 播报时开口，立即停止当前回答的播报和生成，保留已有文字，处理新一轮。
- 连续对话、短语音和打字使用同一个 Agent、SOUL、固定 Skill、记忆检索和当前项目空间上下文。

已有模型沿用当前 DashScope ASR、qwen3-tts-flash-realtime / Cherry 及现有文本模型。用户已确认采用 WebRTC VAD；按固定上游版本保留许可证并编入 App，不增加云模型或密钥。后续新模型或依赖继续先确认。连续对话不采用另一套端到端语音 Agent。

## 交互设计

### 主页长按输入

1. 在非编辑态长按输入框，轻触觉反馈后进入录音态，输入框显示实际转写与“松开发送，上滑取消”。
2. 手指保持按住时持续接收；上滑进入取消态，回滑可恢复；取消不发送消息。
3. 松开结束这一段语音，在获取该段稳定结果后自动发送到开始说话时的项目空间。发送前的短暂整理状态明确可见，并可取消；不弹出每轮确认页。
4. 尚未就绪、没有有效文字或转写失败时保留可恢复输入并提示，不发送空消息或凭空生成内容。不把不稳定字幕冒充最终识别结果。
5. 原有草稿在开始语音前保留，发送语音不会清空原来打到一半的文字。语音按独立消息发送，不擅自拼接到草稿。
6. 现有文字正在生成时，普通短语音仍沿用排队规则；开始说话立即停止当前声音播放。

TextField 的长按与系统光标/选字有冲突。非编辑态的输入框整体支持语音长按；文字正在编辑时保留原生选字，外框空白/麦克风区域仍可按住说话。提供可访问的麦克风按钮作为等效入口，不把功能只藏在手势里。单击仍正常进入打字。

### 连续对话的界面层级

主页双击头像 → 主页内的全屏语音模式，退出返回同一聊天。保留原有四个底部导航，不新增标签页，也不进入会议录音界面。头像菜单保留“连续对话”入口，辅以首次非阻塞提示，便于发现和使用辅助功能。

- 顶部：返回/结束与当前项目空间名称，明确现在与哪个上下文对话。
- 中央：现有紫色 Candid 头像与轻量状态反馈；音量反馈来自实际音频，不伪造声纹。状态文案为“在听”“正在整理这句话”“正在思考”“正在说”“已暂停”“连接中断”。
- 字幕区：用户当前识别文字与 Candid 当前回答，可展开查看聊天记录。字幕沿用米白底、紫色强调、白色圆角区域与现有字体层级。
- 底部：静音麦克风、切换文字、结束。静音后不自动发话；切文字结束语音采集/播放，回到当前聊天，正在生成的文字可继续显示。

默认只在前台持续听，切后台、锁屏、来电或音频路由异常时暂停，不在恢复后悄悄重新开麦。再次点击继续即可恢复。不自动创建另一段聊天或录音场次；文字历史按现有聊天流程保存，不自动保存整场语音为会议录音。

### 自动轮次与打断

- 本机语音活动和停顿检测决定轮次候选，约 1 秒停顿触发封口和自动提交过程；ASR 的句号或一次部分字幕事件不等价于用户说完。真实消息必须等对应音频范围的最终文本完整，不能直接发送 partial。
- 封口时冻结 ASR 子段的 segment_id、采样范围、最后音频序号和子流 ID；麦克风图继续运行。等待旧段 final 时的新音频进入下一子段，不再写入已关闭的子流。
- 若用户在消息提交前继续说话，新子段仍属于同一个 input_turn_id，按无重叠的采样区间合并为该轮完整文本，再等本次停顿；允许同一个逻辑轮有多个已经独立封口的 ASR 子段。不能复用 finishCapture 停掉整张音频图，也不能改写已封口段的时间范围。
- 消息提交边界是客户端持久化不可变文本与 client_request_id 并发起请求的时刻，不是收到服务器 ACK 的时刻。此后补充创建新逻辑轮，在连续模式中打断当前语音回答；即使旧请求 ACK 未返回，也不修改其原正文或复用旧请求 ID。
- 播报时仍保持接收能力，使用 iOS 语音处理/回声消除，以及人声检测，避免 TTS 回声、咳嗽或环境声音轻易触发打断。设备扬声器和耳机需分别实测。
- 检测到有效打断：先本机停播放器并清空旧音频队列、立即接收新语音；再异步取消该语音轮的 Agent/TTS 请求。
- 用 voice_session_id、turn_id、generation_id 区分新旧轮。旧任务的迟到文字/音频不会再次播放，不取消其他空间或无关任务。
- 旧回答已显示部分保留为未完成，未说出的内容不在语音模式自动继续播报。取消失败时明确记录并保留新输入，不声称供应商已停止计算或退款。

### 协议、不完整输入与生命周期

App 的 input_turn_id 与后端 Agent turn_id 不混用。会话保存 owner/后端身份、workspace_id、thread_id、voice_session_id、input_turn_id、client_request_id、task_id、attempt、generation_id 和 TTS 运行 ID 的映射；尚未拿到 task_id 时仍可按请求 ID记录待取消。ACK 到达后先查待取消状态，立即取消旧任务，禁止把它设为当前生成。取消请求保持幂等；所有 ready、final、finished、error、文字和音频事件均验证所属会话、采集 epoch 与生成代。

首次按住/进入模式时，在任何权限或网络 await 之前绑定空间和后端身份，创建采集 epoch。每个异步步骤返回后校验 epoch、操作仍有效及前台状态。上滑取消、退出、暂停、切空间或更换后端使旧采集/播放 epoch 失效，取消停顿定时器；迟到的权限、连接与 final 不得重新开麦、发消息或播放。已提交的文字任务与未提交语音输入分开恢复。

缓冲按时长和字节双限制，并作为命名配置固化：首版预备连接音频默认最多 10 秒/320 KB（16 kHz 单声道 PCM16），待发送网络队列默认最多 2 秒/64 KB。超限、缺帧、ASR 收尾超时或最终结果未覆盖已封口音频范围时，该轮停止自动发送，提示恢复/重说，不静默提交缺词文本。中间字幕可按句合并或替换，但 final 与终止事件不可被普通 partial 挤掉；只丢可替换 partial 且最终结果完整时，不误判成音频缺口。

未提交音频按轮保存在有上限的临时缓冲/加密保护的临时文件，绝不进入会议录音库。取消立即清理；提交正文已持久化且创建结果已确定后清理成功输入。仅 ASR 失败/缺口的可恢复输入可额外保留，带原空间和后端身份，默认最长 24 小时、总量最多 20 MB，超限先提示并清理最旧失败项，不截断当前轮后继续自动发送。未知提交结果保留请求/正文以核对幂等状态；无需永久保留音频。退出清理非恢复数据，恢复项继续按期限管理，不留下无主文件。

后端重启使旧语音生成代终止。重新连接只读取文字和任务状态，不重放旧声音，不把两条 ASR 连接的缺口当作完整一句。用户点击继续开启新 epoch/生成代；未知提交结果先按 request_id 查询，不能盲目再次调用模型。

## 执行顺序与交付条件

### 1. 修复字幕阻断、错误分类与结束顺序（原 P0）

正式后端补齐 RecognitionCallback 导入和异常处理，保留已有 wsproto 依赖修复。验证真实 WebSocket 握手及 ready / partial / final / finished，而不是只看 HTTP 健康检查。鉴权、服务配置及音频协议错误停止自动重试；临时连接错误使用有上限的退避，提供手动恢复。结束时按事件顺序排空已生成结果，final/terminal 走受保护的交付路径，不用固定 sleep 假定最终字幕已经发送。证据与具体问题见 [ASR 定位记录](ASR_LATENCY_DIAGNOSIS.md)。

**交付条件：** 当前 App 到正式后端的真实字幕路径可用；鉴权和连接错误可辨认，不陷入空重连。

### 2. 统一语音轮次、音频所有权与分段计时（前置原 P2）

建立 VoiceSessionController，管理长按与连续模式的状态、空间绑定、轮次和取消。复用/提取已有 ASR 传输与音频播放能力，避免继续向现有大 SpeechController 堆叠状态。用统一音频资源协调器处理麦克风、TTS、回听与录音；会议录音与语音 Agent 不抢占彼此。

这一阶段先交付短语音和连续模式共用的上游就绪/启动缓冲及提交协议，不能把它留到阶段四：区分本机通道和阿里云 task-started；SDK start 返回或 on_open 不等价于供应商就绪。先保留按住后马上说出的音频，即使用户在 ready 前松开也必须完整处理该段，不能静默跳过开头。最终等待有可辨认的超时结果。

资源协调器是唯一可变更 AudioSession 分类、激活状态和音频图的入口。长按、连续模式、历史回答手动播报、会议回听、临时手机会议录音、SDK 实时字幕都经同一租约检查：会议占用时拒绝语音 Agent 入口；连续模式中拒绝抢占的回听/历史播报并提示先暂停/结束模式；不自动结束或删除会议录音。物理设备按键在语音模式中启动会议时，失效语音 epoch、暂停并释放语音资源，再接管 SDK 状态，不据此停止设备录音。旧持有者释放时只能释放自己的租约，不能关闭后来者的图或连接。

复用同一个输入分发服务，而不是直接调用会清空 chatDraft 或读取当前选择空间的 sendChat。它接受开始时绑定的 thread_id、不可变正文和请求 ID，区分 submit 与 answer_input。当前 Agent 明确处于 waiting_input 时，语音默认答复该问题，使用 input_id、expected_attempt 与幂等请求 ID 恢复原任务；不能另建 queued 任务在等待状态后死等。问题已经变化时保留输入并提示，不自动答复别的问题。用户显式选择另起问题时先走现有停止/新建流程。

进入连续模式不自动取消此前的普通文字任务，也不把旧排队任务纳入本轮取消范围。新语音可按既有规则排队；语音轮打断只取消已映射到该会话的当前生成。等待 Agent 提问的回答不通过取消原任务来处理。

状态主线：空闲 → 连接 → 倾听 → 结束一句/整理 → 提交 → 思考 → 播报 → 倾听。播报或思考期间的人声可转到新一轮。暂停、断线和退出均有明确资源释放和恢复路径。

从这一阶段建立不含凭据、音频和聊天正文的分段计时：采集、入队、实际上网、供应商回调、后端发送、App 接收及页面观察更新；记录积压、丢帧、重连与取消。跨设备不直接相减未同步的时钟。调试报告附带实际 TUN/DIRECT/代理路径，不能从环境变量猜测路由；AWS 迁移重新测出口与地域。本轮旧长尾未复现，不将代理或供应商负载标为已证实根因。

**交付条件：** 语音发送与文字发送复用同一任务入口、幂等标识和上下文；ready 前开始并结束的短句不丢开头；waiting_input 回答不堵塞；取消未获 ACK 的旧请求仍能最终定位；切空间结束当前连续语音模式，原消息仍归开始时的空间。

### 3. 交付长按输入

完成输入框手势、上滑取消、实际字幕、自动发送、草稿保留、短语音排队，以及权限拒绝/空结果/网络失败。整合现有手机语音入口，避免出现两套行为冲突的语音输入。

**交付条件：** 按住、松开、取消都可观察；连接未就绪时开始并结束短句仍能完整处理或明确恢复；权限/连接等待中取消后不会重新开麦；不会误清草稿、发空消息、重复发送或串空间。

### 4. 接通连续模式的音频基础与启动缓冲（原 P1）

建立可同时采集与播放的音频图，接通语音处理和回声消除。保持麦克风采集连续，ASR 连接和每轮结果单独管理；音频资源的生命周期不再与某一条语音消息的 finishCapture 绑定。

复用阶段二的就绪和启动缓冲，在连续采集中落实 ASR 子段与逻辑轮的封口/合并协议。加入停顿判定、最终转写等待、重复结果去重及超时恢复。无效声音不触发 Agent。人声刚触发时可立即本机暂时停声；只有确认本轮是有效用户发言后才取消 Agent，不因回声/噪声永久取消任务。确认过程仍在本机，不等网络 ASR 返回才停声。

**交付条件：** 用户可连续多轮说话，每轮自动提交，前后轮字幕不混在一起；暂停/退出后麦克风确实释放。

### 5. 把 TTS 改成真正可打断的流式播放

实施前的手动播报需要完整回答结束，再按最多 800 字分组合成，收齐 WAV 后交给 App。该手动接口保留；新的连续语音输出使用下述 committed 短句与 PCM 通路。

新增面向当前语音轮的稳定短句缓冲，将已生成的完整短句送入现有 TTS 模型，音频片段按序推送并播放；控制合成提前量，避免后续大量音频已经合成但用户早已打断。语义分句与长度共同约束首段，无句号的长句也有受控的切分/等待策略。不朗读工具 JSON、Markdown 符号或未完成 URL；聊天文本保留完整来源，语音层采用可朗读的同义表达，不重写 Agent 事实。

必须先建立后端的“可播报回答提交”通道。当前 runtime 每次模型轮次会 text.reset，而且在是否调用工具判明前已发 text.delta；因此绝不把现有所有 delta 或有句号的工具前导直接送 TTS。完成工具规划/读取后，进入明确禁用工具调用的最终回答阶段，才发布带 generation_id 和稳定序号的 committed speech 片段并逐句播放。工具阶段只提供受控等待状态。已提交播报的正文同时进入可见回答，不能被下一次 text.reset 撤回；打断时保留为未完成。sources 在最终结果完成前按待完成状态展示，不提前捏造或固化引用。

任务预算预留最终回答轮，不以额外未记账调用补这个阶段。无需工具的普通聊天可直接进入无工具回答阶段；需要读取资料的任务先完成工具阶段。取消还需向正在读网络的模型/TTS 连接传播，使旧执行退出，不能只改状态后让新语音一直堵在旧 worker 后；无法及时退出时显示等待取消并保留新输入，不绕过同一对话单活动执行的约束。

waiting_input 的明确追问由后端发布与 input_id/attempt 绑定的 committed prompt 片段，使 Candid 能在语音模式实际提出问题；它不是未经判明的工具前导。用户打断追问时先停止播报，再按该 input_id 答复，不取消等待补充的原任务。若问题已失效，旧 prompt 不得继续播放。

现有 `/v1/chat/messages/{id}/speak` 会拒绝未完成回复，不能直接用于边生成边播报。语音轮需增加与当前任务/generation_id 绑定的短句与音频事件通道；完成消息的手动播报接口继续保留。

对长任务给出明确等待状态，不把未返回的工具结果说成事实。普通聊天的手动播报继续可用。

**交付条件：** Candid 可在全文结束前开始说；用户开口后本机立即停声，旧片段永不串入新轮。

### 6. 整合页面与恢复规则

完成双击头像、全屏语音层、真实字幕、状态、麦克风暂停/继续与切文字。保留项目空间隔离；后台/锁屏/来电/蓝牙变化/后端重启时暂停或退出语音并保留已有文字，不盲目重放/重发付费任务。所有暂停/退出都使旧采集与播放 epoch 失效，取消封口定时器，迟到 final 不触发自动提交；回前台必须由用户点继续，不能自动开麦或重放。

**交付条件：** 用户能明确判断谁在说、App 是否在听，以及当前空间；入口和退出不丢聊天上下文。

### 7. 针对性验收与交付

建议由测开验证长按取消、快速补充、停顿边界、中文/英语/粤语混说、低声与噪声、扬声器回声、耳机、连续打断、旧音频迟到、断网恢复、退出及空间隔离。开发保留事件顺序、幂等、旧代结果丢弃和音频资源回收回归；默认使用本地替身，执行与否以该阶段用户最新测试指令为准。初次实施只进行了构建、源码检查、启动和页面查看；用户随后授权的软件测试已完成：后端 82 项与 iOS 11 项通过。没有进行真实麦克风或付费供应商验收。

旧 ASR 专项验证不是新连续语音已经验收的证据，也不自动覆盖新模型或新的付费压测范围。真实接口验证先说明现有模型、公开样本、调用次数/音频量及目的；已授权的同范围调用不重复请求批准。沿用用户 demo 不设预算限额的决定，不另加收费审批；新增模型/依赖、未授权的专项验证或用户禁止的测试仍先确认。测开按其获得的测试范围执行。

性能记录分成采集、人声判定、ASR 上网/返回、Agent 首句、TTS 首音频和 App 播放，不能只报总延迟。打断停声优先设为约 200 毫秒的开发目标，实际支持范围以真机测量为准；调研等长任务单独衡量，不能统一承诺接话时间。

| 测量段 | 统一起止点 |
| --- | --- |
| 本机打断目标约 200 毫秒 | 本地人声候选事件 → 旧播放器停止且旧队列失效；有效发言确认另记录 |
| 实际开口到停声 | 真机外部录音/可核对声学标记 → 扬声器旧声音消失，包含检测时间，不能与上一行混报 |
| 一轮接话 | 最后有效采样 → 停顿候选 → ASR 最终覆盖 → 提交 → Agent 首个 committed 短句 → TTS 首块 → 实际播放器开始 |
| 恢复与流式持续性 | 连接建立/上游就绪、最大积压、终止事件收到、实际丢帧、补充与取消边界分别记录 |

固定样本哈希、设备、扬声器/耳机路由、冷启动/热连接、实际出口；真实短句基准每个条件至少三次，记录每次及中位数/最大值，不用三次样本声称可靠 p95。长工具任务独立报告。首音频、SwiftUI 观察更新和实际扬声器呈现不能混用指标。

**交付条件：** 本机停止不依赖服务器 ACK，退出后没有残留音频/麦克风任务或无主文件持续增长；真实 iPhone 的麦克风、扬声器、耳机、误打断和回声门槛通过后才对用户开放完整连续模式。模拟器公开样本注入不能替代这项门槛。安克设备不是手机连续语音的前置条件，保留独立 SDK 联调边界。本轮已实现内部版，软件回归通过，真机验收仍待完成；Release 连续模式保持关闭。

## 合并后的依赖与边界

阶段 1 → 阶段 2（含上游就绪与启动缓冲）→ 阶段 3 的短语音内部交付。连续模式依赖阶段 2，阶段 4 的采集/轮次与阶段 5 的可播报正文/流式音频都完成后，阶段 6 只对 Debug/内部开放集成版；阶段 7 真机门槛通过后再完整交付。阶段 3 不依赖设备 SDK 的额外能力，不需要等待流式 TTS；阶段 5 的协议可以先准备，但外放打断必须建立在阶段 4 的回声消除与同一音频图上。

当前实时 ASR 使用供应商公开 duplex 协议，以获得真实 task-started 与显式子流取消；这是协议/生命周期改造，不声称已测得性能提升。原先 SDK 与原生协议的隔离对照仍只作为历史诊断证据。没有更换模型、改变全局代理策略或调低云端端点检测参数。新模型/依赖先确认；已有模型参数改动如影响粤语原话、准确性或交互方向，也先汇报。
