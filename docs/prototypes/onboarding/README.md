# Candid onboarding HTML 原型

2026-10-15。供用户在进入原生 App 实现前确认完整引导。HTML 已获用户确认，原生接入记录见 [onboarding 原生交付](../../ONBOARDING_DELIVERY.md)；本目录继续保留可独立体验的网页原型。

## 预览与操作

在 `projects/CanDidNative` 目录运行；若预览已运行，直接打开 [本地原型](http://127.0.0.1:8877/)：

```sh
python3 -m http.server 8877 --bind 127.0.0.1 --directory docs/prototypes/onboarding
```

欢迎 → 选择用途 → 介绍自己 → 带入资料 → 首页。

| 页面 | 操作与跳过 |
| --- | --- |
| 欢迎 | “认识一下”进入流程；“先体验”或“直接开始”进入首页 |
| 用途 | 销售 BD／面试可多选或取消；单步跳过进入介绍，顶部入口进入首页 |
| 介绍 | 称呼和一段背景均选填；“用说的”展示示例，填入后仍可编辑；可跳过 |
| 资料 | 选择 PDF／DOCX／TXT／Markdown，或加入示例；可移除；“开始使用”或“资料稍后再补”进入首页 |
| 首页 | 查看背景及待整理资料，编辑介绍，体验沟通、聊天与录音入口示意；无重复核对页面 |

回退、单步跳过和直接进入首页均保留已填写内容。用途是初始偏好，不限制后续场景。桌面侧栏可切换页面，“重新体验”清空状态；移动端隐藏侧栏，可刷新重置。状态仅在页面内存中，刷新或重新打开会清空。首页安排至少填写一句内容；底部导航为位置示意。

## 原生实现交接

下列要求已进入原生实现；HTML 仍仅作流程与视觉参考，具体边界见原生交付记录：

1. 持久化引导完成状态，跳过同样算完成；后台恢复、分析或网络失败不应使用户再次被强制引导。
2. 将用户主动提供的称呼、介绍和初始偏好保存为个人资料并可编辑，独立于项目上下文；填写介绍不自动创建可见项目。
3. 用户原话直接保存；AI 产生的新跨场个人结论仍按现有规则集中确认，无重复原话核对。
4. 资料先保存并标为待整理；分析结果与用户输入保持区别，缺少报价、排期或经历时留空，并接入分析、失败与重试状态。
5. 实际录音或设备连接时处理所需权限，复用服务设置，实际分析前说明所用模型服务；跳过资料不构成分析授权。
6. 语音接入真实输入后仍允许编辑转写文字，维持回退与跳过保留输入、资料可后补、首页立即可用的行为。
