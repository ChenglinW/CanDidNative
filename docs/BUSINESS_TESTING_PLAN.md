## 建议的验收方式

沿同一条销售链路测：**前两场资料 → 第三场会前简报 → Mock → 录音 → 分人和问答 → 共识与行动 → 客户跟进 → 项目追踪 → 下一场复用**。面试复用项目与场次骨架，另外验证 JD/简历依据、本人贡献和练习隔离。

把测试分成四层，报告分别记结果：

1. **业务规则**：用可控的合成资料和标准答案，测归属、权限、确认、版本、发送状态、恢复。适合自动化回归。
2. **模型质量**：公开数据集加人工标注的业务案例，测听对、分对、提取对、回答有据、信息不失真。
3. **真实设备与服务**：录音豆、手机、实际转写和语音服务，测同步、时间轴、并行采集、延迟和失败恢复。
4. **决赛流程**：按表格的「台上真跑 / 预置数据 / 仅口述 / 不演示」排练，核查数据来源、耗时和降级标识。

公开数据最适合第 2 层。第 1、3、4 层还需要专用案例和真实操作，无法由一个通用数据集覆盖。

## 公开数据集怎么选

下列「首轮抽样」是启动建议，不是已下载或已通过的数量。先取官方开发/验证集调试，保留独立测试集；同一会议及其片段不得跨开发与验收两边。

| 数据集与官方入口 | 适合本业务的测试 | 首轮抽样建议 | 标注与边界 |
| --- | --- | --- | --- |
| [AISHELL-4 / OpenSLR 111](https://www.openslr.org/111/) | 中文转写、重叠发言、多人分离、时间轴，映射表格 39–41 行 | 保留现有 20 片段回归，再补来自不同会议的 40 片段和 3 场完整会议 | 普通话会议音频、转写与说话人活动；120 小时、211 场。发布页标 CC BY-SA 4.0。没有销售承诺、本人身份或客户姓名的标准答案。 |
| [AliMeeting / OpenSLR 119](https://www.openslr.org/119/) | 近场/远场对比、2–4 人分人、重叠与漏人，映射 40–41 行 | 验证集先选 3 场，固定近场/远场输入条件 | 118.75 小时会议，带转写；发布页标 CC BY-SA 4.0。与 AISHELL-4 交叉验证，不能当成录音豆的真实采集效果。 |
| [AliMeeting4MUG / 作者实现](https://github.com/alibaba-damo-academy/SpokenNLP/tree/main/alimeeting4mug)，[数据入口](https://www.modelscope.cn/datasets/modelscope/Alimeeting4MUG/summary) | 中文会议主题、摘要、行动项检测，映射 13–15、18 行 | 10 场人工转写，补标 50 条行动及其负责人/日期 | 官方任务含主题分段、抽取摘要、标题、关键词、行动项检测。行动项检测不等于完整「谁/做什么/何时」标注；负责人、日期、内外可见性需补标。作者代码 Apache-2.0 不代表数据同许可，本轮未从动态数据页确认数据许可。 |
| [QMSum / Yale-LILY](https://github.com/Yale-LILY/QMSum) | 「王总之前关心什么」「上次怎么回答」这类带依据的会议问答，映射 6、14、74–75 行 | 按会议抽样，累计 50 个 query；原始英文独立报告 | 232 场会议、1,808 组 query-summary，具体问题有相关原文范围。仓库标 MIT；关联原始会议资料按其来源记录。不是多次销售推进的现成完整数据。 |
| [LongMemEval cleaned / 作者数据](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)，[作者说明](https://github.com/xiaowu0162/LongMemEval) | 跨场检索、知识更正、时间推理、不知道时拒答，映射 16、38、71–75 行 | 先做 50 题，覆盖知识更新、跨场、时间、拒答；同题跑 Oracle 与正常检索两种输入 | 官方 500 题，数据卡标 MIT。保留问答发生日期和证据会话 ID。只把标准答案放评分端；用户确认、撤回、项目权限是另加的业务规则，不能声称原数据已覆盖。 |
| [AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/) | 连续会议中的决策演变、需求变化和项目状态，映射 16、46、50、81 行 | 选同一设计团队的 1 组连续会议，再补标阶段变化 | 约 100 小时；部分是贯穿项目始末的设计团队情境，公开音频/转写及部分标注标 CC BY 4.0。可借鉴多场结构，但不是销售或招聘实录。若与 QMSum 共用底层会议，要按原会议 ID 去重。 |
| [FLEURS / Google](https://huggingface.co/datasets/google/fleurs) | 普通话、英文、粤语的语言基础覆盖，映射 40、55、77 行 | 每种语言抽 20 条，分语言统计 | 音频加参考转写，数据卡标 CC BY 4.0。主要是朗读语音，不能据此验收多人会议、中英混说或语音打断。混说需另录。 |
| [CraigslistBargain / 作者实现](https://github.com/stanfordnlp/cocoa/tree/master/craigslistbargain)，[作者论文](https://www-nlp.stanford.edu/pubs/he2018decouple.pdf) | 报价变化、还价、条件句、同意与未同意的区别，映射 15、22–23、53–54 行 | 可选第二轮 30 段谈判，人工标价格、条件与达成状态 | 买卖谈判领域比闲聊更接近销售，但不覆盖 B2B 审批和跨场项目。官方 README 链接旧 Codalab，本轮未验证数据包可下载及独立数据许可，不作为首轮依赖。 |

首轮优先顺序：**现有 AISHELL 资产 → AliMeeting4MUG → QMSum → LongMemEval cleaned**；AMI 用于补多场结构，FLEURS 补语言覆盖，CraigslistBargain 作为候选扩展。

英文数据翻译成中文后应另建版本，人工校核姓名、数字、否定和条件，结果标为衍生测试集。不能把翻译分数或改编销售脚本分数冒充原始 benchmark 分数。

## 最值得先做的一套销售测试素材

采用虚构客户「华味」，同一团队录三场，每场 3–5 分钟，另建无关客户作为隔离对照。脚本在录音前写好标准答案，录后由人工核对实际说出的内容；演员漏说的句子不能进入音频标准答案。

| 场次 | 脚本事实 | 本场结束后的预期状态 |
| --- | --- | --- |
| 第 1 场：2026-10-19 10:00 +08:00 | 客户明确有 30 家门店；王总问接口和上线时间；我方 J 说「2026 年 10 月 20 日 18 点前发案例」；上线时间待技术确认；「6 家愿意试用，还没开始」 | 两个问题待答；一个带明确负责人/日期的行动；试用只是意向；不产生正式交付承诺。 |
| 第 2 场：2026-10-21 10:00 +08:00 | J 明确案例已发送；李工说接口文档仍没拿到；「如果接口可用，评估两周部署，最终排期未定」；内部另记审批未过 | 发案例行动完成，有来源；接口仍是缺口；两周仍是条件估计；内部审批不能进客户外发稿。 |
| 第 3 场：2026-10-22 10:00 +08:00 | 李工提供接口文档并回答接口问题；王总说「可以评估试点，但采购还没批」；双方没有确认上线日期 | 接口问题补答且保留前两次出现记录；采购/试点仍未批准；不标成交，不新增上线期限。 |

会前测试：用前两场生成第 3 场四块简报，必须知道案例已发、接口仍缺、王总关注点及排期待确认。只凭两场会议不能推断长期表达能力已经改善。

外发测试：稿件应保留第 3 场共识与明确下一步，不能出现内部审批详情、擅自折扣、批准采购或承诺两周上线。没有明确下一步时应保留待确认，不能为填满版式创造任务。

干扰组：另一客户记录特有词「青柠项目底价 137 元」，但从未关联华味。对华味项目的回答、简报、Mock、外发稿中均不得出现该事实。再使用另一 owner 做同样检查。

面试素材：虚构简历只写「需求访谈、流程设计」，JD 要求数据分析；本人明确「改善了，但没统计时间」。预期可以建议补证据，不能写「效率提升 30%」或把别人的带队职责归本人。另录一轮 Mock，核对练习不会修改真实场次行动及表现统计。

## 指标与建议门槛

下面是本项目的首轮验收建议，不是公开数据集官方标准，也不是本轮已达到的成绩。先看各类样本和失败明细，不能只看一个总分。

| 指标 | 计算方式 | 首轮建议 |
| --- | --- | --- |
| 业务硬性规则 | 检查越界读取、AI 自行确认、内部信息外发、错误发送状态、重试重复写入、已删除数据被任务恢复 | 固定验收集 0 例；任一出现即挡演示/交付。零失败只适用于本样本范围。 |

## 怎么定位一条错误

对同一批案例跑三个入口：

1. **人工正确原文 → 当前业务分析和问答链路**：隔离模型的理解、提取、检索问题。
2. **原始音频 → 实际录后转写 → 同一业务链路**：观察转写/分人如何传导成负责人、金额或承诺错误。
3. **录音豆 → App → 服务器 → 页面与导出**：发现设备、同步、任务状态、交互和时间轴问题。

旧 `scripts/evaluate-aishell4.py` 主要是短片段 Qwen ASR 与本人文本复盘，不能直接代表当前 `tasks/recordings.py` 的长音频 Filetrans、分人、录音整理、业务复盘路径。新增适配器时优先复用真实业务入口，禁止只测试临时拼出来的相似提示词。

每个案例至少保存：case_id、原表行号、项目/场次/owner、样本来源和版本、输入文件哈希、实际录音日期与时区、说话人映射、证据版本/时间点、标准字段、禁止出现的事实、实际输出、任务/供应商运行 ID、各阶段耗时、成功/失败、人工判定及原因。模型、提示词、量表、分段和数字规范化规则应随运行记录固定。

标准答案与判分标签只给评分端；历史对话按时间进入系统。项目三场测试不能提前给第一场分析器提供第三场结果。公开集若参与调提示词，须另留未使用会议作为验收集。新增的时间、身份、可见性标签标明是人工扩展，不算官方原始标注。
