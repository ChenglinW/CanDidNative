# CanDid V2 实现与验收

2026-10-16。执行依据：[用户批准的范围](../prompts/UI_V2_IMPLEMENTATION_AND_ACCEPTANCE.md)、[原样 HTML](../references/CanDid_v2_iPhone17_20261016.html)、[设计约定](../../DESIGN.md)。最终提交与部署记录见同目录 DELIVERY.json。

## 本轮实现

原生 SwiftUI 主入口已替换为 **Candid／记忆库／录音**，采用一个持久 Chat。主页正常字号固定为一张已就绪准备卡、最近三场录音；缺少的部分隐藏。真实新用户显示空态，合成内容只在隔离的 Debug 验收参数下出现。旧项目页、多会话选择器、单独手写长期资料入口退出新版产品路径。

Chat 从底部展开，关闭后保留同一个视图与线程；草稿和阅读位置沿用本机恢复机制。报告只读，结束场次在“全部准备包”列表操作。首页和 Chat 使用同一个准备包 ID；主动录后消息、首页、录音列表和原文使用同一个 recording_id。

记忆库包含长期文件、表达积累、跨场发现。文件支持 PDF／DOCX／PPTX／TXT／MD，实际保存解析文字与页号。表达自动积累并保留原文、时间戳、来源版本，用户可修改；新跨场个人结论集中确认一次。一个 Chat 可按需检索全部历史，不受首页三条限制，不把未知说话人的经历当作本人经历。

录音处理自动衔接最终 ASR、复盘、表达积累、Chat 主动消息；重复处理与同一录音修订更新原卡片，不重复通知。录音中“问 Candid”读取当前字幕的不可变快照，明确为未经校准的临时内容；重试绑定原问题与原快照，普通检索不混入临时字幕。

手机输入框长按、松开发送／上滑取消、连续对话、WebRTC VAD、TTS 和 SDK 仍沿用已配置能力。连续对话保留头像双击及明确按钮；未连接时增加直接重连入口。会议录音优先安克设备，手机会议录音作为次要备用。

## 相对 HTML 的变化

| 内容 | 本轮处理与理由 |
|---|---|
| 三入口、固定首页、单 Chat、淡紫准备卡、暖橙报告按钮 | 保留原型结构与 Warm 视觉语言 |
| 头像、图标、导航 | 复用已有 Mascot 与 SF Symbols；iOS 27 系统 tab、安全区及返回行为使用原生实现 |
| 长按输入、连续对话 | 用户批准保留，增加明确按钮、连接恢复及 Reduce Motion 降级 |
| 会议录音 | 用户批准保留手机备用入口，放在录音／设备引导中 |
| Onboarding、销售与面试 | 按用户确认保留，个人介绍可跳过及稍后编辑 |
| 设置、全部准备包、结束场次、错误重试 | 原型未完整画出但业务必需，放入次级入口；不把报告变为编辑表单 |
| 大字号与 iPad | 内容可滚动、控件换行；不强求无障碍字号仍维持固定一屏 |
| 演示资料、旧项目／多会话选择 | 正常使用路径移除；Git 留档，内部任务及来源 ID 不向用户暴露 |
| 旧版项目专用页面 | 项目归档、客户跟进撰写／内部同步表单、项目追踪及独立练习页未迁入三入口；复盘保留建议跟进，Chat 可继续据资料问答 |
| 旧录音辅助操作 | 独立的录音手动标签编辑、项目关联及报告文件导出入口没有带入首轮 V2；已有数据／后端能力保留，不将它们列作新版入口验收通过 |

## 要求与验收对应

| 要求 | 入口／接口 | 已运行证据 |
|---|---|---|
| 空首页、三入口，无假数据 | CompanionHome / RecordingShell | XCUITest V2EmptyHome；原生完整截图 |
| Chat、草稿、键盘、收起、切 tab | ChatView / recovery | XCUITest V2ChatDraft；键盘真实存在且输入框位于其上 |
| 连续对话可找到 | 首页按钮、Chat 按钮、头像双击 | XCUITest V2EmptyHome；实际语音服务另见真实接口与硬件边界 |
| 准备包持久化、Chat／首页相同 ID | save_preparation / companion | 后端排序／版本／结束回归；原生实际 HTTP 链路；真实模型保存结果 |
| 多份／待定／过期准备 | companion snapshot、全部准备包 | 同客户新版本替换、其他客户不受影响；过期保留、明确结束 |
| 相对日期与手机时区 | profile.timezone、任务快照 | 有效 IANA 时区校验，任务冻结时区并传入模型；未提供日期不编造 |
| 超过三条及不同客户检索 | companion 全局资料范围 | 五场录音检索、客户甲乙事实区分、真实模型引用资料 |
| 长历史摘要 | SummaryStore 批次与检查点 | 至少三批摘要保留最早目标、最新待办与消息引文，重复运行复用检查点 |
| 来源修订／删除、用户编辑 | SQLiteMemoryAdapter / 表达详情 | 原文删除传递两层衍生依据；旧版本排除；用户表达不被重处理覆盖 |
| 录后自动复盘与主动消息 | recording_knowledge job | 实际异步作业回归；真实 ASR→复盘→表达→恰好一条主动消息 |
| 说话人姓名与本人 | 原文→说话人认领 | Swift 模型与表单 XCUITest；未知身份不会自动成为本人 |
| 文件真实解析 | 记忆库上传／onboarding documents | 中文多页 PDF、DOCX、PPTX、TXT、MD；扫描／损坏明确失败；加密／空文件后端回归；Swift 文件复制大小校验 |
| 当前字幕提问 | LiveRecordingView / live-ask | 超过上下文时使用最新尾段，问题／快照／录音绑定冲突返回409 |
| 排队、停止、恢复 | Agent tasks / event cursor | 单 Chat 第一轮取消保留片段、第二轮继续；事件游标无缺失重复；重启中断不自动重放付费请求 |
| 单用户隔离、未授权引用 | owner-scoped domain | 并发唯一 Chat、跨用户访问及证据范围回归 |
| ASR／TTS／打断协议 | WebSocket voice routes | 真实中英粤流式、最终分人及 TTS；模拟重复／取消／序号／旧输出隔离 |
| 设备入口与失败恢复 | 录音页／设备引导／SDK | 原生入口测试、模拟器硬件初始化保护；录音豆物理链路待设备 |

## 实际发现与根因修复

| 发现 | 根因与修复 |
|---|---|
| 新版主页进不去原有问答入口 | 重建真实三 tab 与驻留 Chat，入口直接绑定同一个线程 |
| 录音被动等用户请求复盘 | 完成 knowledge job 时保存表达并原子发布主动消息，录音 ID 唯一；转写修订更新同一消息 |
| 模型说“准备好了”却没有报告卡 | 明确准备任务在没有 save_preparation 持久化结果时不能完成；按工具协议补保存或补问 |
| 排队与主动消息交错后回答错轮 | 当前任务输入从历史中移出，作为最后一条用户消息进入模型；历史时间线仍按创建顺序展示 |
| 删除原资料后衍生条目还能读到 | 来源解析递归验证父依据和版本，删除／失效向衍生链传递 |
| 未认领录音产生版本假失效 | 统一原始版本与增加身份注记后的规范版本候选，不把计算字段当作证据修订 |
| 长摘要或一场长录音挤掉其他依据 | 摘要分批并检查点恢复；跨场抽样分摊到多个场次 |
| Monid 结果出现 DSML 工具语法 | 上游偶发把工具语法发在 content；SSE 跨片段屏蔽控制标记，要求通过正式 tool_calls 重发，仍受原预算与取消约束 |
| 普通点按误触按住录音 | 长按第一阶段提前启动，且外层输入容器手势覆盖发送按钮。改为长按成立后的第二阶段收音，仅输入区承载手势，发送按钮独立；真实 ASR 开启场景定向回归 |
| 本机 HTTP 验收误进离线模式 | XCTest 自动隔离覆盖了显式验收配置；Debug 模拟器使用隔离验收目录和明确 opt-in，正常 Release 不含绕过 |
| 二次输入失焦 | 后台发布刷新原先走阻塞式 loadChat，未编辑输入区域还禁用了 TextField 命中；改为静默刷新、校验当前任务／消息未变化再应用，输入框保持可点击，真实 App 二次发送回归通过 |
| 字号／键盘、对比度、连接恢复 | 原生截图与几何断言定位；大字号控件换行、日期紫色、连接动作与上推动效同时修正 |

Monid 一轮遇到90秒上游超时，未算通过；后续定向复测完成。没有通过放宽断言掩盖错误，也没有更换用户批准的模型。

## 实测质量与延迟

以下是这次小规模合成样本的链路记录，不是人群准确率或网络服务承诺。

| 样本 | ASR 就绪 | 就绪后首字幕 | 规范化 CER |
|---|---:|---:|---:|
| 普通话，5.84秒 | 0.747秒 | 0.718秒 | 0% |
| 英语，3.60秒 | 0.666秒 | 0.738秒 | 0% |
| 粤语 | 0.689秒 | 0.682秒 | 4.17%，省略“嘅” |
| 三语轮流＋低噪声 | 0.666秒 | 0.745秒 | 2.83%，包含汉字数字形式差异 |
| 同时重叠双人 | 0.941秒 | 0.774秒 | 无单一逐字参考；英语被覆盖，不能作为重叠识别通过 |

19.35秒的轮流混合录音，最终转写到复盘完成约32.8秒；返回三组分人 ID 和逐句时间戳。合成语音分人不等于真实多人 DER 已验证。准备包真实模型保存一轮约22.0秒；Monid 最终完整搜索／正文／回答约94.9秒。语音 Agent 一轮首文字约6.63秒、首音频约7.45秒，接收99840字节 PCM 并完成取消验证；这是软件音频回执，没有假定扬声器已经播放。

## 复现

1. 使用 Python＋reportlab、ffmpeg、macOS say 运行 `python3 scripts/generate-v2-fixtures.py`。清单见 [fixture-manifest.json](fixture-manifest.json)，作者合成文本 CC0，音频来源为 macOS Tingting／Samantha／Sinji，固定噪声种子；不下载未知许可的人声。
2. `backend/.venv/bin/python -m pytest backend/tests -q`。
3. 启动 `backend/.venv/bin/python scripts/v2-test-server.py`，另开终端执行 `TEST_RUNNER_CANDID_RUN_HTTP_UI=1 sh scripts/check-ios.sh --test <模拟器UDID>`；固定本机验收令牌只属于隔离测试服务，无云模型 Key。
4. `backend/.venv/bin/python scripts/validate-v2-cloud.py --checks all --output <新结果路径>` 调用真实已配置服务并清理临时用户；有实际模型用量。
5. `backend/.venv/bin/python scripts/validate-v2-native-cloud.py --device <模拟器UDID> --result <新xcresult路径> --output <新json路径>` 执行原生 App 的真实 HTTPS 链路；临时访问令牌仅在子进程环境传递，保留日志会脱敏，finally 删除临时用户。

## 外部条件与明确缺口

- Mac 和已连接 iPhone 当前均自动锁屏；签名钥匙串需要用户解锁后才能更新手机安装。模拟器 UI、后端、真实模型调用及不签名 Release 构建继续完成。
- 真人麦克风、真实回声下 WebRTC VAD、TTS 开口打断、系统打断与后台生命周期仍需解锁真机并实际发声补验。软件状态／取消／顺序测试不替代声学验证。
- 没有安克录音豆；SDK 初始化保护、入口及协议已测，录音豆按钮、蓝牙同步和 SDK 是否提供实时 PCM 仍需硬件。
- 扫描 PDF 当前不做 OCR，密码保护或不可读取的文件提示恢复办法；不是上传成功后假装读到了正文。后续可独立接 OCR。
- ASR 重叠语音样本丢失英语，已在证据中保留；真人中英粤混说、方言与噪声覆盖还需要更大的公开或自有授权语料。
- 飞书多维表格同步仍按此前确认留到下一阶段；本轮没有发送外部邮件、微信或 WhatsApp。
