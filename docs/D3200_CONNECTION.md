# D3200 连接与实时音频

2026-10-16。本轮目标是让用户直接连接录音豆，不填写 SDK 参数。

## 用户流程

录音 → 录音设备 → 连接与同步。App 自动取得授权、请求蓝牙权限并查找设备。首次选择录音豆后，按页面提示将录音豆放回充电盒，在灯闪烁时按充电盒按钮确认。绑定确认及设备身份读取完成后才显示已连接。已验证过的设备在下次进入前台时会尝试重连，重试有次数边界；主动断开后不会立即自动连回。更换设备只清除 App 的记住状态，不发送解绑或清空录音指令。

首次开机：去掉录音豆触点保护膜，取出后放回充电盒，确认左侧指示灯亮起。无需先在 iPhone 系统蓝牙设置里配对。资料来源：[官方连接说明](https://service.soundcore.com/article-description/How-do-I-connect-the-soundcore-Work-recorder-to-the-soundcore-app)、[D3200 官方说明书入口](https://service.soundcore.com/article-description/soundcore-work-User-Guide-D3200)。官方消费版 App 的账号及导航说明不等同于本项目 SDK 接入要求。

按录音豆按钮开始与结束录音；App 无远程开始/结束 API。录音开始后，从录音页的本场录音入口查看实时原文；首次需确认参与者已知情。手机会议录音备用入口、手机语音输入及连续对话继续保留。

## 本轮定位与修正

1. 原来复用的旧框架实际自报 `V1.0.98`。从原始工具资料包提取的正式 iOS Release 框架自报 `D3200 / V1.3.01`，匹配云端已开通的版本。准备脚本不再因 Vendor 已存在就跳过更新；单元测试会检查运行时版本，不能只看压缩包文件名。
2. 旧文档给的是 CI 地址，组织者提供的成功示例实际使用 QA 地址。新的服务端 token 交换使用 `https://speaker-api-qa.anker-in.com/v1/third_party_sdk/get_token`，发送真实 SDK 产品号/版本头和秒级 Unix 时间戳。原文档的毫秒描述不适用本次实际接口。
3. 真机扫描日志确认 `productCode` 返回空值。旧版严格比较 `D3200` 导致全部设备被过滤。现在保留 SDK 回调，按名称/服务信息优先展示录音豆，其余设备收在“其他附近设备”中，兼容广播信息不完整的情况。
4. SDK 文档与 iOS Demo 对扫描 UUID 的描述不一致。本项目按官方 iOS Demo 使用 `020cf5da-0000-1000-8000-00805f9b34fb` 服务 UUID 调用设备 API。真实手机已完成发现、连接、充电盒确认、序列号核对和设备录音列表读取。
5. 原实现以 `onRealtimeTransferSwitch` 为 BLE 实时音频请求的前提；集成文档明确此回调是 Wi-Fi 模式专用。现在收到录音开始状态即可调用 `acquireRealtimeAudioData`，无需等待 Wi-Fi 通知；暂停后继续可重新请求。字幕通道已连上而设备尚未发出音频时，页面明确显示等待音频。
6. 服务 UUID 由同型号设备共用，不再作为录音所属设备的唯一 ID。新录音关联采用设备序列号，未取得序列号时才使用 MAC，避免不同录音豆同一文件时间戳串场。既有后端录音不会删除或改写。

## 服务与凭证

后端 `POST /v1/soundcore/authorization` 使用现有 App 登录认证，由服务器确定 user_id。客户端只上报稳定的手机 UUID、实际产品号和 SDK 版本。`device_id` 是手机身份，不是录音豆 SN。

服务端配置 `SOUNDCORE_APP_ID`、`SOUNDCORE_APP_KEY`、`SOUNDCORE_ENVIRONMENT=qa`；正式授权配置可设置 `production`，不提供任意主机代理。凭证位于服务器受限环境文件及本机忽略的 `.env.soundcore.local`；团队共享通过现有加密配置包。app_key 不进入 App、Git 明文、诊断或报告。

服务端授权缓存按用户/手机/型号/版本/环境隔离，按服务返回的 token 和 license 有效期提前刷新，并设置 `Cache-Control: no-store`。SDK 授权及验证过的设备保存在 Keychain，关联当前后端账号；删除记忆时清除本机 SDK 授权。不会复用聊天中提供的示例 token。

连接诊断仅在本机 Caches 保留最近 120 条状态、错误码、扫描产品信息、音频帧计数等，不记录 token、license、app_key、音频或原文；序列号仅记录哈希。可用开发工具读取 `Library/Caches/SoundcoreConnectionDiagnostics.json` 排查，属于运行资料，不提交 Git。
