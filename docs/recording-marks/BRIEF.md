# 录音标记重点

模式：Operate / Read；code-led，延续 Warm 与实色页内分段，不重设视觉系统。

双击 D3200 表示“关注这里”，不要求类型选择或当场填写。实时显示轻量标记，最终设备文件的毫秒列表落到既有 marks；本机保留待上传列表，恢复相同后端身份后重试。SDK 头文件明确最终时间为相对本音频的毫秒偏移；实时每帧20ms，超过三小时续传只展示收到标记，精确时间以文件为准。

复盘前置“你标记的重点”，展示片段标题、摘要、时间与多个原点。近邻标记按原文范围合并展示；原始点不合并删除。片段支持回听/暂停、逐句播放、展开原文、改标题、移除重点、带上下文问既有 Agent。

重点摘要是当前录音的派生结果，跟随原文和标记更新；不是个人长期记忆。FAQ／表达／跟进复用已有提取与引用，动态展示关联，不额外创建平行知识。标记不证明表达有效、承诺成立或谁是本人，不触发外部发送或自动全网调研。取消标记不删除原文和已存在知识；跨场新个人结论沿原集中确认规则。

最小验收：实时/离线重复回调去重；晚到标记补分析；修订后重算且手改标题保留；既有FAQ/行动仅关联不复制；账号隔离与断线待传；手机/平板、根与详情大字号、音频与Agent HTTP流程。物理双击/暂停/离线的落点需要真机操作验证，不用模拟器替代。


## 原文增强（2026-10-16 调整）

标记在后续分析之前统一处理：`transcript_enrichment.enhance_transcript` 根据可见标记取前30秒／后15秒原文，在供模型阅读的副本中为明确数字插入「系统标记提示·非原话：注意这个数字」，无明确数字时追加「用户标记关注此处」。支持中文及阿拉伯数字、金额、数量、百分比和日期；不推断承诺、正负评价或本人身份。此步骤为本机规则，不增加模型调用。

复盘及 FAQ 已撤回 `user_marks_ms` 和标记专用 prompt；跨场分析复用相同前置函数，原有后续 prompt 与记忆确认规则保持不变。持久化转写、逐句播放、说话人及证据版本均使用原始数据，增强副本不写回数据库、不展示为用户原话。隐藏标记或原文修订后，下次分析从当前原文重新准备；不批量重写已经完成的历史知识。现有重点卡片、独立片段摘要、问答及动态关联保留。


## 语义前置增强（替代规则注释）

前置处理沿用现有文本模型，理解标记焦点及其前后完整句子。相邻标记先合组，每个连续话题尽量只写一条语义说明；空泛口头确认不单独标注。数字作为含单位、范围与角色的整体理解，区分预算、起售价、落地价、估计和承诺；含糊转写不偷偷纠正。

`recording_marks` 的同一个持久任务同时生成重点卡片和带原句证据的语义注释，复盘／FAQ／跨场分析的前置读取等待或复用这个结果，不各自调用模型。缓存绑定语义版本、现有模型、转写版本和可见标记。隐藏、修改来源后重新计算；人工标题保留。失败、取消或缺少已有模型授权时直接使用原始转写，不退回逐数字规则，也不自动重复提交失败调用。

注释只追加到分析副本有实质内容的原句后，不替代原文；片段读取缺少注释支持的证据时不附加该注释。旧有复盘、FAQ、跨场 prompt 逐字不改，输出解析及记忆确认规则也不改。FAQ 的数量与重复程度如实比较，本轮不加硬条数限制或下游合并器。
