# 录音标记重点：文档对齐

2026-10-16。本次为既有 Warm 系统的普通页面扩展，方向以 [BRIEF.md](BRIEF.md) 为准；文档静态核对 `RecordingHighlights.swift`、`CompanionUI.swift`、`RecordingUI.swift` 与 `backend/recording_marks.py`，不改变全局 token 或重设视觉。

## 产品边界

D3200 双击只表示「关注这里」，不要求当场分类或填写，也不推断赞同、负面评价、说话人身份或标记原因。实时状态轻量提示已收到，录后在复盘正文前置「你标记的重点」；每项展示标题、摘要、多个原始时间和标记次数。无原文或摘要尚在整理时保留真实等待说明，允许先看原文及回听，不填充示例。

SDK 头文件已明确：最终 markers 是相对本音频的毫秒偏移；实时每帧为 20ms。超过三小时续传时只提示收到标记，精确时间以最终文件为准，不能用实时字幕或推算落点宣称硬件时间已校准。本机待上传点在相同后端身份下重试，账号隔离沿用既有规则。

## 阅读与操作

重点列表沿用 Warm 紫色书签、语义字体与轻分隔线，通过原生导航进入详情；详情沿用 18pt 水平内边距、最大 700pt 单列及至少 44pt 操作范围，保持米白浅色世界。复盘／原文继续使用既有实色分段；页头、播放器及大字号降级仍服从原录音页布局。标题菜单、原生改名 sheet 和既有立体主要按钮沿用原组件，不添加单独主题、token 或新的确认步骤。

详情提供片段摘要、主题、回听／暂停、原文句子与逐句播放、展开完整原文、修改标题、移除重点和「围绕这一段问 Candid」。提问带当前片段及时间范围进入既有 Agent；用户不必复制原文建立另一段上下文。失败、中断和继续整理使用真实任务状态；退出详情停止该录音回听，音频冲突仍按现有资源规则处理。

## 来源、修订与记忆

近邻点只按原文范围合成展示片段，原始 marks 不合并删除；当前服务端取每个点前 30 秒、后 15 秒覆盖的原文，重叠且合并后不超过两分钟时共同展示。取消以隐藏原点控制重点可见性，移除整段隐藏该组原点；原文、音频及已经存在的 FAQ／行动继续保留。

重点摘要是单场录音的派生结果，原文版本、标记或原文范围变化后重新整理；用户手改标题作为独立覆盖保留。摘要、主题和下一步建议依据当前原文，不自动创建事实、任务、提醒或个人长期记忆，不把提议当承诺、不把标记当效果证明。

「相关 FAQ 与表达」以及「已整理的跟进与待核实」从现有 `library_items` 和 `project_items` 的原文引用动态关联，打开原条目，不复制成新知识库。原有客户范围、归属与来源权限继续有效；AI 新形成的跨场个人结论仍走既有集中确认，标记本身不增加确认流程，也不触发外部发送或自动全网调研。

## 证据与收尾

文档工作仅完成源码与方向约定的静态对齐。主任务已报告本轮 320 项后端测试通过；该数字不是本文单独执行的结果，完整构建、iPhone／iPad 大字号、音频与 Agent HTTP 验证以主任务最终记录为准，不据此宣称部署完成。

物理设备双击、暂停、离线同步及超过三小时续传的精确落点尚未实机验收；模拟器、测试夹具和界面截图均不能替代这些证据。真机安装和启动状态以本轮主任务记录为准。后续验收需分别记录软件测试、视觉结果和物理链路结果。

本轮仅新增此记录，并在 `PRODUCT.md` 录音规则及 `DESIGN.md` 录音约定处各补一句入口；既有视觉系统、记忆库规则及历史验收记录保留原范围。
