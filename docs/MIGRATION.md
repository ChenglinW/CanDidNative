# 从本机迁移服务器

本轮不部署 AWS。后端可在服务器运行，App 只更换地址及访问令牌；模型密钥和 Monid 仍留在服务器。

1. 安装 Python 3.12、requirements 与 ffmpeg；从私有渠道导入队友配置包，正式设置 `CANDID_RECORDING_MODE=device`。
2. 停止写入后备份 SQLite，或用 SQLite backup API 在线备份；同时备份整个 `CANDID_DATA_DIR` 下的 storage。只拷贝数据库会丢失音频、PDF、精转写分段和 TTS 文件。
3. 数据目录包含原文、标签修订、知识、自动个人记忆、任务/事件、摘要、供应商运行ID、费用和本机访问令牌；保持服务用户最小权限。配置文件0600。不要上传至公开仓库。
4. 前置 HTTPS 反向代理，允许 SSE 和 WebSocket，调整音频上传请求大小和超时。局域网服务需显式 `--lan`；公网正式鉴权使用当前 Supabase 边界或另行确定方案，不能公开裸本机令牌服务。
5. 使用稳定对象存储及受限签名 URL 替代 demo 临时 OSS。确认其费用/账号后配置，不在本轮擅自创建桶或云资源。
6. `GET /v1/memory/export` 包含全部业务表与短时音频链接；这不是完整文件备份。整库删除有所有者墓碑，递归删除其存储目录并阻止旧任务重建资料。删除录音原音频同步清理本机后端 ASR 分段；转写和保留的资料按现有规则继续保存。
7. 同事服务接入时同时迁移 App 写入、Agent 读取、修订、确认、自动归档授权和删除流程；只迁移一个读取入口会形成两份库。真实接口尚未提供，当前保持 SQLite。
8. 后端重启的 Agent/业务任务标为中断，手动继续；带供应商 run ID 的任务先查询原任务。未收到提交回执的付费请求保留不确定状态，不盲目重发。

迁移后的公网、容量与真机流程由测开另行验收；本轮只有本机编译/启动。
