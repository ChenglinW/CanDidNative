# 连续对话 Release 开放与验证

2026-10-16。用户明确要求解除连续对话限制并测试；不改变已有模型、服务地址或音色。

## 改动

`VoiceSessionController.enter` 原先在非 DEBUG 编译中仅设置“连续对话暂不可用”，不会启动网络或音频。现统一显示连续对话页并走原来的 `begin(continuous:true)` 路径。后端与 ASR 就绪、活动空间、麦克风权限、独占音频租约、VAD、停顿封口和打断取消均保留。

新增跨构建回归：无服务就绪条件时，Release 入口也应打开页面，但不获取麦克风。测试宿主的 XCTest 识别覆盖 Release，使测试不自动连接真实云端；普通已安装 Release 不接受调试隔离启动参数。说话人单元测试改为在测试目标内构造 fixture，避免 Release 测试依赖 DEBUG 页面样本。

- Release：入口可进入且保留就绪检查、VAD 静音分帧、音频租约冲突，共 3 项测试通过。

## 真实云端链路

使用独立新建的测试设备身份及 Mac 合成语音，不使用手机 owner 或既有个人对话。通过当前 HTTPS 服务执行与 App 相同的协议：

1. `/v1/speech/live` 流式传入 16kHz 单声道 PCM，约 2.532 秒收到上游 ready，之后 0.753 秒收到首条字幕；完整转写“你好，请用一句话介绍你自己。”，97914 字节确认完整、无音频缺口。
2. `/v1/voice/turns` 将该最终文本交给实际文本 Agent，`/v1/voice/output/{task_id}` 返回“我是 Candid，一个陪你一起准备沟通、复盘表达的中文伙伴。”及 230400 字节非零 PCM（24kHz，4.8 秒）。从提交文本至首段音频约 7.144 秒。
3. 另发一轮并通过请求 ID 取消，回执与任务状态均为 cancelled。

以上是单次冒烟结果，不是延迟分布。音频播放回执由脚本模拟，仅证明云端转写、生成、音频传输及取消；不能替代手机扬声器实际播放和真人打断。测试身份的数据已删除，旧令牌查询返回 410 Gone；手机资料未改动。

## 真机边界

安装已成功；自动启动首次被 iOS 锁屏拒绝（Locked）。已请用户解锁后进入“问 Candid”，说一句话并在播报中插话。真人麦克风、手机外放、回声误触发和实测打断延迟等待该轮反馈；不把云端脚本的取消当成真机 VAD 打断通过。测试时关闭 Device Hub 手机屏幕共享，避免已观察过的全零采集干扰。
